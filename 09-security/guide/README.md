# 案例导引

这套材料用于让学生结合 AI 完成 09-security 案例。目标是让学生自己想清设计，AI 只负责把想法写成代码。

## 为什么不直接发代码

本模块现有的 `README.md`、`docs/09-security-build.md`、`lecture.html`、`requirements.html` 都是完整实现。学生拿到这些再结合 AI，产出的是复制粘贴，代码能跑但讲不出为什么。

导引的做法是把“要什么”和“怎么写”分开：先只给契约，学生自己定设计，逐关验证，最后才发参考实现做对照。

## 发放节奏

| 时机 | 发什么 | 学生产出 |
| --- | --- | --- |
| 第 0 天 | `contract.md`、`spec-template.md`、`ai-prompt.md`、`pitfalls.md`、`check.sh` | 填好的规格说明 |
| 规格通过后 | `guide-01-auth.md` | 能登录、能鉴权、401 正确 |
| 关卡 1 通过后 | `guide-02-authorize.md` | 三个角色权限点分开 |
| 关卡 2 通过后 | `guide-03-ownership.md` | 归属判断成立，越权 403 |
| 关卡 3 通过后 | `guide-04-frontend.md` | 前端联调走通 |
| 四关全过后 | 完整代码（`src/`、`web/`）、`build.html`、`lecture.html` | 对照阅读笔记 |

规格说明是第一个卡点。学生把“接口与权限点的对应”和“归属判断放在哪层”写不清，就先别放去写代码，那两节空着的实现必然出问题。

## 每关给什么、扣什么

| 关卡 | 给 | 扣 |
| --- | --- | --- |
| 1 认证 | 接口契约、错误码、账号表、BCrypt 要求 | 过滤链怎么组、令牌怎么签、401 怎么返回 JSON |
| 2 授权 | 角色与权限点对照表、每个接口的权限要求 | 两个比对方法的差异、方法级鉴权的开关在哪 |
| 3 归属 | 越权规则、状态流转、两个业务码 | 判断放哪层、当前登录人怎么传进去 |
| 4 前端 | 字段清单、四类错误的分流要求、走查清单 | 拦截器怎么串、路由守卫怎么写 |

扣掉的部分都在 guide 的“卡住了看这里”里有三级提示，从方向到具体位置，都不给代码。学生卡住时按顺序看，看到能自己想下去为止。

## 验收

`check.sh` 覆盖 24 条行为，分四关。起好后端执行：

```bash
./check.sh        # 全部
./check.sh 1      # 只跑关卡 1
./check.sh 2 3    # 跑关卡 2 和 3
```

前端没有自动化，按 `guide-04-frontend.md` 里的十项走查清单人工过。

第 23 条依赖新建 `student99`。库里已有这个账号时脚本会跳过并提示，重启后端即可恢复干净的种子数据（`schema.sql` 每次先删后建）。

## 一个要注意的地方

`check.sh` 只能证明行为对，不能证明代码是自己写的。要分辨，看两处：

- **规格说明和实现对得上吗**：学生写“归属判断放服务层”，代码里是不是真在服务层。写和做不一致，说明是 AI 写的别人家的设计。
- **问他的取舍**：为什么令牌不放权限点、为什么归属判断不在控制层。`pitfalls.md` 里每一条都可以当面试题。

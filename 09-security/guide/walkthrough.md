# 从零实现：二十步与提示词

这份手册按顺序走完，系统就能跑起来。二十步与 `docs/09-security-build.md` 严格对应，那份是贴完整代码的实现版，最后对照阅读时并排看。

每一步给你三样东西：要做什么、怎么问 AI、怎么验证。代码不在这里给。

## 怎么用

**AI 当审查者，不当代笔。** 直接说“帮我实现登录接口”，拿到的是 AI 的设计，你只是打字员。改成自己先写一版，再让它挑错，学到的东西完全不同。下面提示词按这个思路设计，多数是问方案和问取舍，少数才轮到自己写不出来时再要代码。

**一次只问一个决策点。** 一次问五个问题，AI 会挑容易的答，难的含糊过去。问完一个，确认了再问下一个。

**报版本和现状。** 不说版本，AI 默认给你 Spring Security 5 的写法，那个年代用的配置基类现在早删了。不说手上有哪些类，它会另起一套，跟你后面的代码打架。

**过不了验证就不走下一步。** 每步末尾都有验证命令和期望结果。第 09 步登录不通就接着写前端，后面只会更难查。

**先跑通再读代码。** 编译不过、接口不通的时候读代码毫无意义。

## 第一步之前

数据库先准备好，`backend_learning` 库会自动建。MySQL 要跑起来，账号密码记下来，第 02 步要用。

提示词里的版本按本机实际填：Spring Boot 4.1.1、Spring Security 7.1.1、MyBatis-Plus 3.5.17、jjwt 0.13.0、MySQL 8.4、Vue 3.5.44、Vite 8.3.5、TypeScript 5.9.3。

第 01 步的提示词假设你是在现有工程里加模块。如果是新建一个独立工程，把“父 POM 是 spring-boot-starter-parent 4.1.1”直接说成“用 Spring Initializr 生成，版本 4.1.1，打包方式 jar”，其余不变。

# 一、打地基

## 01 · 建模块，把依赖版本定死

六个依赖，哪些版本由父 POM 管，哪些要自己写。

问 AI：

```text
Maven 多模块工程，父 POM 是 spring-boot-starter-parent 4.1.1，我要加一个模块。

依赖清单：
- spring-boot-starter-security
- spring-boot-starter-validation
- com.baomidou:mybatis-plus-spring-boot4-starter
- com.mysql:mysql-connector-j
- io.jsonwebtoken:jjwt-api、jjwt-impl、jjwt-jackson

问题：
1. 哪些不用写版本号，谁在管？
2. jjwt 三个包各自的 scope 应该是什么，为什么 impl 和 jackson 不需要编译期可见？
3. 这个工程同时有 Jackson 2 和 Jackson 3，两者会冲突吗？

只回一张表：groupId、artifactId、版本、scope、谁管版本。不要写完整 pom。
```

产出 `09-security/pom.xml`。

验证：`mvn -pl 09-security dependency:tree | grep -E 'security|jjwt|mybatis'`，能看到 Security 7.1.1、jjwt 0.13.0、MyBatis-Plus 3.5.17。

写种子数据时注意：时间不要用 `NOW()` 减小时数。清晨启动会算出凌晨三五点，页面上一条凌晨的提交记录一眼就假。用“日期随当天滚动、时刻固定”的写法。

验证：启动后执行

```sql

SELECT LEFT(password, 4) FROM sec_user LIMIT 1; -- $2a$
SELECT status, COUNT(*) FROM sec_task GROUP BY status;
```

## 03 · 统一响应体与错误码

所有接口一个外壳，错误码成表。

问 AI：

```text
前后端分离，令牌认证，Spring Boot 4.1.1。

问题：业务失败（密码错误、任务已批改这类）返回 HTTP 200 加业务码，还是返回对应 4xx？两种做法下前端的响应拦截器分别怎么写？

有个约束：有一种情况无论如何都得用真实状态码，不做成 200 包业务码。你判断是哪种，说明理由。
```

产出 `Result`、`ErrorCode`、`BusinessException`、`GlobalExceptionHandler`。

`ErrorCode` 里 4xx、5xx 与 HTTP 状态码对齐，业务错误用 3 开头的五位数。密码错误和用户名不存在共用 30001，分开提示等于告诉别人哪些用户名存在。

验证：`curl -i http://127.0.0.1:8009/public/ping --noproxy '*'`，返回 `{"code":200,"message":"success","data":{...}}`。

```text
1. 菜单按角色显示，和路由守卫重复吗？只做其中一个会出什么问题？
2. 登录页的错误提示，和别的页面的错误提示，应该共用一套样式还是各写一套？
```

产出外壳、顶栏、登录页。

验证：登录成功后进得去，顶栏显示当前账号与昵称。

## 19 · 三个业务页面

页面本身不难，难在三种状态的处理一致。

问 AI：

```text
三个页面：学生任务页（列表 + 提交 + 详情）、教师批改页（全部列表 + 打分）、账号管理页（列表 + 新增 + 删除）。

问题：
1. 加载中、空列表、请求失败，这三种状态怎么用同一套模式处理，避免每个页面各写一遍？
2. 统计数字（总数、待批改数、平均分）在页面里算还是要后端加接口？判断依据是什么？
3. 三个页面的表格结构差别不小，该抽公共组件还是各写一份？

不引 UI 组件库，样式手写。
```

产出三个页面。

验证：三个角色各登一次，页面内容对得上身份：学生看不到批改入口，教师看不到账号入口。

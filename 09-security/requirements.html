01项目定位与规模

这门课的能力目标是“能独立交付一个带登录、带角色、带归属判断的接口模块”。讲完 Spring Security 的组件清单，学生还是不知道一个业务模块里权限该写在哪一层、前端该配合什么。所以拿一条真实的业务线做载体：学生交作业，教师批改，管理员管账号。

它在 15 个模块里的位置：前面 04-web 已经统一了响应体与异常处理，05-mybatis 已经会写 Mapper 和事务，本模块把这两块接上安全能力；后面 10-file 传附件、11-doc 出接口文档，都建立在这里的登录态之上。

为什么不用一堆示例接口演示

零散的 /demo/admin、/demo/owner 能把注解讲清楚，但学生没法把它们拼成作业。换成一条业务线之后，每个鉴权点都有业务理由：为什么学生不能看别人的提交，为什么教师能改分数，为什么管理员不能删自己。

系统边界

只做任务提交与批改这一件事，周边能力一律留给后面的模块：文件上传在 10-file，接口文档在 11-doc，缓存与分布式锁在 06-redis，监控在 13-actuator。这里刻意让自己只依赖一个 MySQL，别的中间件都不装，学生克隆下来就能跑。

02使用者与权限模型

三类使用者，三套权限。管理员没有提交作业的权限，教师不能建账号，学生除了自己和全班列表之外看不到任何人的数据。

行为学生 STUDENT教师 TEACHER管理员 ADMIN判定位置
登录、看当前身份✓✓✓匿名可访问 /auth/login
提交任务✓——权限点 task:submit
看自己的提交✓✓✓登录即可，URL 里没有用户名
看别人的单条提交—✓✓服务层比对归属，越权 403
看全班提交列表—✓✓权限点 task:review
批改、打分—✓✓权限点 task:review
看账号列表——✓URL 规则 /admin/** 要 ROLE_ADMIN
新增、删除账号——✓权限点 user:write，且不能删自己

角色给人看，权限点给接口用

角色只有三个，权限点有五个，由角色枚举摊平后写进 UserDetails。接口上的注解只认权限点，将来多一类人（比如教务），加个角色、配好权限点就行，Controller 一行都不用改。

角色权限点典型用途
STUDENTtask:submit、task:read提交作业，看自己的列表与分数
TEACHERtask:review、task:read看全班，批改，查任意一条
ADMINuser:read、user:write、task:read、task:review管账号，顺带能看全部提交

四种鉴权粒度

同一个模块里四种写法都出现了，因为它们解决的问题不一样。学生在作业里最容易犯的错，是拿其中最松的一种去套所有场景。

粒度写在哪例子什么时候用
URL 规则SecurityConfig 的 requestMatchers/admin/** 要 ROLE_ADMIN整片路径的使用者是同一类人
角色类上的 @PreAuthorize("hasRole('ADMIN')")账号管理整组这一组接口只给一个角色
权限点方法上的 @PreAuthorizehasAuthority('task:review')同一组接口里不同动作门槛不同
数据归属Service 里比对 owner_id看详情、看我的列表接口对所有人开放，但只能碰自己的数据
第四种最容易被漏掉

/api/tasks/{id} 对登录用户开放，注解查不出问题，因为学生确实有 task:read。真正拦住他的是服务层那句归属比对。只写注解不写归属判断，改一下 URL 里的 id 就能看别人的作业。

04业务规则与错误码

七条业务规则

编号规则为什么这么定
BR-1归属只从令牌取请求体里的 owner 一律忽略。前端能改的字段，就不能用来做权限判断
BR-2归属存 owner_id，不存用户名用户名将来可能改，改完历史记录就找不到主人了
BR-3同一任务在待批改状态下不能重复提交避免学生连点产生多条；批改之后允许重交，算补交
BR-4已批改的不能再批改分数一旦给学生看就是结论，要改分数得走另外的流程
BR-5密码只存 BCrypt 密文自带盐，同一密码两次加密结果不同，库被拖走也难反推
BR-6令牌有效期 120 分钟，不做刷新教学取舍。刷新令牌与黑名单放在练习里，见第 09 节
BR-7401 和 403 分开返回401 是没认出你是谁，前端跳登录；403 是认出了但不够格，前端只提示，不能把人踢下线

错误码

4xx 与 5xx 跟 HTTP 状态码对齐，3xxxx 是业务错误。业务错误大多数仍是 HTTP 200，靠 code 区分；只有 401 与 403 会改状态码，因为前端要靠它决定行为。

code含义HTTP出现场景
200成功200所有正常返回
30001用户名或密码错误200登录时账号不存在或密码不对，两种情况提示语一样，不告诉对方账号是否存在
30002账号已被禁用200密码对了但 enabled 为假
30003用户不存在200删除一个查不到的账号
30004用户名已存在200新增账号撞唯一键之前先查一次
30005不能删除当前登录账号200管理员删到自己，防止把唯一的管理员删没
30010任务不存在200批改或查看一个不存在的 id
30011同一任务已提交，等待批改200重复提交同标题的待批改任务
30012该任务已批改，不能重复批改200教师对同一条打第二次分
400参数错误200校验失败、JSON 解析失败、路径参数类型不对
401未认证或令牌已失效401没带令牌、令牌过期、签名对不上
403无权访问该资源403角色不符、权限点不够、看了别人的任务
404资源不存在200路径写错，落到静态资源兜底
500系统繁忙200未预料的异常，日志里留堆栈，响应里不出现

06接口契约

前后端分离之后，契约就是唯一的事实来源。三条约定写清楚，联调时少一半来回。

统一响应结构
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1,
    "title": "实训一：用户登录接口",

编号约定
C-1响应外层固定 code、message、data 三个字段，data 在失败时为 null
C-2请求带令牌时统一写 Authorization: Bearer <token>，不加前缀一律按未认证处理
C-3前端先看 HTTP 状态码，再看业务 code。401 清登录态跳登录页并记住来处，403 只提示，其他状态码按失败处理

选型理由

每个选择都能说清“为什么不选另一个”，这门课的学生迟早要在项目里做同样的判断。

选型理由没选的做法
Spring Boot 4.1.1课程主线版本。4 起 web starter 拆成 spring-boot-starter-webmvc，Jackson 默认升到 3，这些差异本身就是工程化的一部分Boot 3.x：资料多，但与当前主线脱节
MyBatis-Plus与 05-mybatis 同一套写法，学生不用学第二遍。单表走 BaseMapper，联表还能写注解 SQL，SQL 始终在自己手里JPA：自动生成的 SQL 不好排查，学生遇到慢查询无从下手
MySQL真实环境是什么就用什么。表名加前缀后，十个模块共用一个库H2：启动快，但建表语法、字符集、时区都与线上差一层
jjwt 0.13.0Spring Security 6 与 7 都不提供 JWT 签发，jjwt 是事实标准，API 稳定，三件套的依赖范围也清楚OAuth2 Resource Server：要额外跑授权服务器，一个案例讲不完
BCrypt自带盐，同一密码两次结果不同；慢哈希，暴力破解成本高；强度参数可调MD5 / SHA-256：无盐、可撞库，加盐也要自己写
Vue 3 + TypeScript前后端分离是这个模块要教的事。TS 让接口字段改名在编译期就报，而不是等到页面上显示 undefinedThymeleaf 服务端渲染：讲不出令牌、拦截器、路由守卫这一套
Vite 加代理开发期同源，不涉及 CORS；冷启动一秒内，改代码即时生效webpack：配置重，学生要多学一层与业务无关的东西
不引 UI 组件库只有四个页面，手写样式反而让注意力留在鉴权链路上，源码里没有一行和主题相关Element Plus：好看，但引入一整套组件与主题变量，排查问题时多一层
权限点留在枚举角色与用户的绑定是运行期数据，权限点是代码资产，跟着接口一起评审。要配置化时加两张表即可权限点建表：多两张表与一套管理界面，本模块讲不到

08架构与分层

后端分层

包职责不做什么
controller接请求、校验入参、写注解声明谁能调不写业务判断，不碰 Mapper
service业务规则、归属判断、事务边界不出现 HTTP 相关类型
mapper单表走 BaseMapper，联表用 @Select 返回投影对象不写业务判断
entity表映射，字段与列一一对应不出 service 层，不作为接口出参
model领域对象 Account、状态枚举、联表投影不依赖表结构变化
dto / vo入参校验 / 出参白名单vo 里不出现密码这类敏感字段
security令牌签发与解析、过滤器、UserDetails 适配、401 与 403 出口不做业务
config过滤链、认证管理器、密码编码器、跨域不写业务
common统一响应、错误码、业务异常、全局异常处理不依赖任何业务包

没做的理由去哪补
刷新令牌、登出黑名单要引入 Redis 存黑名单，属于 06-redis 的地盘；本模块令牌 120 分钟够演示课后作业一
登录失败次数限制、验证码同样是 Redis 计数，且与业务主线无关课后作业一
按钮级权限现在只到菜单与路由级。按钮级要在 UserProfile 里下发权限点，前端写指令课堂练习四
分页与后端筛选28 条一次返回，前端算统计更方便。上分页时平均分不能拿当前页算，要单独出聚合接口课堂练习三
权限点配置化需要权限表与一套管理界面，超出本模块容量结课项目
文件上传作业附件涉及存储与下载鉴权10-file
接口文档OpenAPI 与在线调试单独一个模块11-doc
缓存、消息队列、定时任务本模块没有对应的性能与异步场景，为了用而用会讲不清06 / 07 / 08
一条必须说清的话

前端守卫只管体验。有人改一下 localStorage 就能进页面，但进去以后每个接口都是 403，什么也拿不到。权限判断永远在后端，前端做的只是别让用户白点。

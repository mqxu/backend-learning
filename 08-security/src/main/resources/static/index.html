08-security · 认证与授权

一份进程里跑着五个阶段，同样的代码配不同的规则，行为可以直接对照。

阶段一全局拦截

任何请求都要认证。可用 Basic 认证测试三种身份：

  • curl -i http://127.0.0.1:8008/stage1/hello → 401
  • curl -u bob:123456 http://127.0.0.1:8008/stage1/hello → 200

阶段二放行白名单

公开接口与 GET 请求放行，写操作仍要登录。

  • /stage2/public/info → 匿名可访问
  • /stage2/articles/1 → 匿名可访问

阶段三角色与权限点

hasRole / hasAnyRole / hasAllRoles / hasAuthority 四种判断的差异：

  • bob（ADMIN + AUDITOR）能过 /stage3/audit/logs，carol（只有 ADMIN）过不了
  • erin（只有 AUDITOR）能过 /stage3/ops/alerts，过不了 /stage3/admin/reports

阶段四表单登录

Session + CSRF，浏览器里点一遍最直观。

  • 打开登录页
  • /stage4/me → 未登录会 302 跳登录页

阶段五前后端分离

无状态 JWT + 短信验证码登录，接口全部返回 JSON。命令见模块 README。

  • POST /api/auth/login → 密码换 token
  • POST /api/auth/sms/code?phone=13800000002 → 发验证码
  • POST /api/auth/sms/login → 验证码换 token

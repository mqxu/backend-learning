# 07 联调与排错

## 启动顺序

1. MySQL（3308）
2. 后端（8080）
3. 小程序 H5（5174）或管理后台（5173）

后端没起来时前端只会提示网络异常，看不出具体原因，所以先确认后端：

```bash
curl -s http://127.0.0.1:8080/api/ping
```

正常返回：

```json
{"code":0,"message":"ok","data":{"status":"up","service":"campus-activity"}}
```

## 自动化验收

```bash
./scripts/smoke.sh
```

脚本走完整链路，20 项断言：

| 分组 | 覆盖内容 |
| --- | --- |
| 健康检查 | 后端可达 |
| 登录绑定 | 两个学生登录、绑定学号 |
| 创建活动 | 组织者建活动拿到 ID |
| 审核 | 提审、管理员登录、待审核列表包含该活动、审核通过 |
| 报名 | 报名成功、重复报名被拒（30002）、满员进入候补 |
| 签到 | 取签到码、轮换周期、签到成功、重复签到被拒（40003）、伪造签到码被拒（40001） |
| 统计 | 已签到 1、候补 1、到场率 100 |

全通过说明后端主链路可用。脚本每次会新建一场活动，可以反复执行。

## 手工验证片段

登录并保存 token：

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:8080/api/app/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"devOpenId":"mock-student-1"}' | jq -r '.data.token')
```

查活动列表：

```bash
curl -s "http://127.0.0.1:8080/api/app/activities?page=1&size=5" \
  -H "Authorization: Bearer $TOKEN" | jq '.data.records[] | {id,title,statusLabel,signupOpen}'
```

报名：

```bash
curl -s -X POST http://127.0.0.1:8080/api/app/activities/3001/signup \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{}' | jq
```

注意：本机若配了代理，curl 访问 127.0.0.1 可能连不上，加 `--noproxy '*'`。

## 常见错误对照

### 返回 401

token 过期或没带。默认有效期 2 小时。重新登录即可。

### 10003 请先绑定学号

报名接口要求先绑定。用 `POST /api/app/auth/bind` 绑定，演示学号 `2023001` 到 `2024002`。

### 20005 报名尚未开始 / 已结束

报名时间窗由活动的 `signup_start_time` 与 `signup_end_time` 控制。

### 30001 名额已满

活动 `capacity` 已满且未开启候补。把 `waitlist_enabled` 设为 1 后满员会进候补而不是报错。

### 30002 你已报名该活动

同一用户对同一活动只能有一条有效报名。唯一索引 `uk_activity_user` 也会拦下并发重复提交。

### 30004 已超过取消报名截止时间

默认截止是活动开始前 2 小时。演示时可以把活动的 `cancel_deadline` 往后调：

```bash
mysql -h127.0.0.1 -P3308 -uroot -p'Campus@2026' campus_activity \
  -e "update activity set cancel_deadline = date_add(now(), interval 1 day) where id = 3001"
```

### 40004 当前不在签到时间内

签到窗口是「活动开始前 30 分钟 到 活动结束后 30 分钟」。示例活动在几天后，直接签到会被拒绝。要演示签到，以组织者身份新建一场 30 分钟内开始的活动，或调整活动时间：

```bash
mysql -h127.0.0.1 -P3308 -uroot -p'Campus@2026' campus_activity \
  -e "update activity set start_time = date_add(now(), interval 20 minute), end_time = date_add(now(), interval 2 hour) where id = 3001"
```

### 40001 签到码无效或已过期

签到码每 30 秒换一个时间片，服务端只接受最近 2 个时间片。重新获取 `checkin-qr` 即可。如果服务器与手机系统时间差超过 1 分钟，会一直失败，检查机器时间。

### 40005 不在签到范围内

活动 `checkin_type = 2`（扫码 + 定位）时，要求签到时经纬度距场地 200 米内。演示时把 `checkin_type` 改成 1，或传入与活动一致的经纬度。

### 后端启动后端口不是 8080

环境变量里的 `SERVER__PORT` 会被 Spring 的宽松绑定识别成 `server.port`，优先级高于 `application.yml`。启动时显式指定：

```bash
mvn spring-boot:run -Dspring-boot.run.arguments="--server.port=8080"
```

### 小程序里请求全部失败

按顺序检查：

1. 开发者工具是否勾选了「不校验合法域名」
2. `request.js` 里的 `BASE_URL` 在真机上是否为电脑的局域网 IP
3. 手机与电脑是否同一网段
4. 后端是否监听在 `0.0.0.0`（默认是），防火墙是否放行

### H5 页面能打开但接口 404

`vite.config.js` 的代理只在 `npm run dev:h5` 生效。直接打开构建后的静态文件、或把 `BASE_URL` 改成绝对地址 `http://127.0.0.1:8080/api` 时，需要后端允许跨域——`WebMvcConfig` 已经放开了全部来源，仅用于开发。

### 列表少了一条数据

所有业务表都有 `deleted` 逻辑删除字段，MyBatis-Plus 全局配置会自动追加 `deleted = 0`。手工在数据库里改数据时不要动这个字段。

## 重置演示数据

```bash
cd server/src/main/resources/db
mysql -h127.0.0.1 -P3308 -uroot -p'Campus@2026' campus_activity < schema.sql
mysql -h127.0.0.1 -P3308 -uroot -p'Campus@2026' campus_activity < data.sql
```

重置后所有报名、签到记录清空，活动时间重新按当前时间计算。

## 日志

后端启动日志写到 `server` 目录下的控制台输出。用后台方式启动时建议重定向：

```bash
mvn spring-boot:run -Dspring-boot.run.arguments="--server.port=8080" > /tmp/campus-server.log 2>&1
tail -f /tmp/campus-server.log
```

SQL 日志已打开（`mybatis-plus.configuration.log-impl`），调试时可以直接看到执行的语句与参数。上线前把这行去掉，否则日志量很大。

## 2. 概念铺垫

### 2.1 为什么需要消息队列

同步调用：用户下单 → 直接调库存、通知、物流…… 一环卡住全链路都慢，且各服务强耦合。

引入消息队列后：下单服务把「下单成功」这件事**发出去**，谁关心谁订阅，各消费者**异步**处理。好处：

- **解耦**：生产者和消费者互不直接调用；
- **削峰**：瞬时高并发先进队列，消费者按自己能力慢慢消费；
- **异步**：非核心流程不阻塞主流程。

### 2.2 核心模型

RabbitMQ 的三个关键概念：

| 概念 | 作用 | 类比 |
| --- | --- | --- |
| Exchange（交换机） | 接收消息并按规则分发 | 邮局分拣中心 |
| Queue（队列） | 存储消息，消费者从这里取 | 收件人的信箱 |
| RoutingKey | 决定消息路由到哪个队列 | 收件地址 |

常见交换机类型：`direct`（精确匹配 routingKey）、`topic`（通配符匹配）、`fanout`（广播到所有绑定队列）。

## 3. 环境准备

1. 安装并启动 RabbitMQ（默认 `localhost:5672`，账号 `guest/guest`）；
2. 依赖：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-amqp</artifactId>
</dependency>
```

配置：

```yaml
spring:
  rabbitmq:
    host: localhost
    port: 5672
    username: guest
    password: guest
    # 生产者确认
    publisher-confirm-type: correlated
    # 消费者手动确认
    listener:
      simple:
        acknowledge-mode: manual
```

## 4. 动手实战

> 本模块当前是骨架，下面带你逐步补全消息能力。

### 步骤 1：声明队列、交换机、绑定

```java
package top.mqxu.mq.config;

import org.springframework.amqp.core.*;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

/**
 * RabbitMQ 配置
 *
 * @author mqxu
 */
@Configuration
public class RabbitConfig {

    public static final String ORDER_EXCHANGE = "order.exchange";
    public static final String ORDER_QUEUE = "order.queue";
    public static final String ORDER_ROUTING_KEY = "order.created";

    @Bean
    public DirectExchange orderExchange() {
        return new DirectExchange(ORDER_EXCHANGE);
    }

    @Bean
    public Queue orderQueue() {
        return QueueBuilder.durable(ORDER_QUEUE).build();
    }

    @Bean
    public Binding orderBinding(Queue orderQueue, DirectExchange orderExchange) {
        return BindingBuilder.bind(orderQueue).to(orderExchange).with(ORDER_ROUTING_KEY);
    }
}
```

讲解：

- `durable` 队列持久化，重启不丢消息；
- 常量集中定义 exchange/queue/routingKey，避免各处写魔法字符串。

### 步骤 2：生产者发送消息

```java
package top.mqxu.mq.controller;

import lombok.RequiredArgsConstructor;
import org.springframework.amqp.rabbit.core.RabbitTemplate;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import top.mqxu.mq.config.RabbitConfig;

/**
 * 消息生产者
 *
 * @author mqxu
 */
@RestController
@RequestMapping("/order")
@RequiredArgsConstructor
public class OrderController {

    private final RabbitTemplate rabbitTemplate;

    @PostMapping
    public String createOrder(@RequestBody String orderJson) {
        rabbitTemplate.convertAndSend(
                RabbitConfig.ORDER_EXCHANGE,
                RabbitConfig.ORDER_ROUTING_KEY,
                orderJson);
        return "下单成功，消息已发送";
    }
}
```

### 步骤 3：消费者接收消息

```java
package top.mqxu.mq.listener;

import lombok.extern.slf4j.Slf4j;
import org.springframework.amqp.rabbit.annotation.RabbitListener;
import org.springframework.stereotype.Component;
import top.mqxu.mq.config.RabbitConfig;

/**
 * 订单消息消费者
 *
 * @author mqxu
 */
@Slf4j
@Component
public class OrderListener {

    @RabbitListener(queues = RabbitConfig.ORDER_QUEUE)
    public void onOrderCreated(String message) {
        log.info("收到订单消息：{}", message);
        // 模拟异步处理：扣库存、发通知……
    }
}
```

讲解：

- `@RabbitListener` 监听队列，有消息就回调；
- 消费者跑在独立线程，不阻塞生产者。

### 步骤 4：消息可靠性（确认与重试）

目标：消息不丢、不重复处理。

- **生产者确认**：`publisher-confirm-type: correlated` 打开，发送方知道消息是否到达交换机；
- **消费者确认**：`acknowledge-mode: manual` 手动确认，处理成功才 ack：

```java
@RabbitListener(queues = RabbitConfig.ORDER_QUEUE)
public void onOrderCreated(String message, Channel channel,
                           @Header(AmqpHeaders.DELIVERY_TAG) long tag) throws IOException {
    try {
        // 业务处理
        channel.basicAck(tag, false);   // 成功，确认
    } catch (Exception e) {
        channel.basicNack(tag, false, true); // 失败，重新入队
    }
}
```

### 步骤 5：死信队列（处理失败消息）

目标：重试多次仍失败的消息，别无限重试，转去「死信队列」人工处理。

```java
@Bean
public Queue orderDeadQueue() {
    return QueueBuilder.durable("order.dead.queue").build();
}

@Bean
public Queue orderQueue() {
    return QueueBuilder.durable(RabbitConfig.ORDER_QUEUE)
            .withArgument("x-dead-letter-exchange", "")
            .withArgument("x-dead-letter-routing-key", "order.dead.queue")
            .build();
}
```

讲解：消息被 `basicNack` 且不再入队时，会路由到死信队列，便于排查。

## 7. 常见问题与避坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 连接失败 | RabbitMQ 未启动 / 账号错 | 核对 `spring.rabbitmq` 配置 |
| 消息发出去没人消费 | 队列/交换机/绑定没声明 | 确认 `Binding` Bean 存在且 routingKey 一致 |
| 消息重复消费 | ack 丢失或失败重试 | 消费逻辑做幂等（如唯一键去重） |
| 消息丢失 | 队列未持久化 / 未开确认 | 队列 durable + 生产者确认 + 手动 ack |
| 无限重试 | 失败一直 nack 入队 | 引入死信队列，重试有限次后转人工 |

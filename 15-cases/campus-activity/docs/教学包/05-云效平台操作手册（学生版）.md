## 1 云效产品总览

### 1.1 云效五件套是干什么的

云效（阿里云一站式 DevOps 平台）把「想需求 → 写代码 → 构建 → 测试 → 部署」串在一条线上。本课程用到其中 4 个产品 + 2 个选讲产品：

| 产品 | 解决什么问题 | 本项目怎么用 | 本课程要求 | 官方文档 |
| --- | --- | --- | --- | --- |
| 项目协作 Projex | 需求、任务、缺陷、迭代、看板、工时 | 每组 1 个项目；24 条任务、8 条缺陷、2 个 Sprint、每日站会记录 | 必做 | [什么是云效](https://help.aliyun.com/zh/yunxiao/product-overview/what-is-cloud-effect) |
| 代码管理 Codeup | 代码托管、分支保护、合并请求（MR）、代码评审 | 每组 1 个代码库；`main`/`develop`/`feat`/`fix` 分支；MR 评审 | 必做 | 云效帮助中心「代码管理」 |
| 流水线 Flow | 自动构建、测试、制品上传、部署到主机 | `campus-activity-ci`：`mvn test` → `mvn package` → 制品 → ECS 主机部署 | 必做 | [Java 应用构建并部署到 ECS](https://help.aliyun.com/zh/yunxiao/user-guide/build-and-deploy-a-java-application-to-an-ecs-host) |
| 制品仓库 Packages | 存放构建产物（jar、tgz） | 可选：把 `app.jar` 存入 Packages；不存也能完成本课（用流水线公共制品存储） | 选做 | 云效帮助中心「制品仓库」 |
| 测试管理 Testhub | 测试计划、测试用例、执行结果、关联缺陷 | 第 3–4 次课建测试计划，≥12 条用例，执行后关联缺陷 | 必做 | 云效帮助中心「测试管理」 |
| 应用交付 AppStack / 效能洞察 Insight | 应用编排、研发效能数据 | 第 4 次课选讲：看迭代速率与流水线成功率 | 选讲 | 云效帮助中心对应产品 |

> 产品入口：登录云效后，顶部通常有「工作台 / 项目 / 代码 / 流水线 / 制品 / 测试」等导航；也可以在云效控制台首页搜索产品名。**以云效当前界面为准**。

### 1.2 五个产品在你的一天里怎么串起来

```
早上站会（Projex 看板）→ 领任务 → 拉分支（Codeup）→ 写代码 → 提 MR → 同学评审 → 合并
      → 流水线自动跑（Flow：测试/构建）→ 需要时部署到 ECS → 发现 bug 建缺陷（Projex）
      → 测试计划里登记用例与结果（Testhub）
```

| 时点 | 你在云效做什么 | 对应课程产出 |
| --- | --- | --- |
| 课前 | 加入组织、认领任务 | 环境就绪报告 |
| 课中 | 更新看板、提 MR、评审 | 检查点通过 |
| 课后 | 完成任务、闭环缺陷、准备测试 | 过程分证据 |
| 第 4 次课 | 跑流水线、部署、发版、答辩 | 成果分证据 |

### 1.3 账号与权限的层级

| 层级 | 你需要什么权限 | 谁给 |
| --- | --- | --- |
| 阿里云账号 | 能登录云效 | 自己注册（建议实名，见 2.2） |
| 云效组织成员 | 访问组织内项目/代码库 | 教师发邀请链接 |
| 项目成员 | 建/改任务、看板、缺陷 | 组长或教师添加 |
| 代码库开发者 | 推分支、提 MR | 组长在代码库成员里添加 |
| 流水线运行 | 触发/查看流水线 | 教师或组长配置 |
| 主机组 | 只读/触发部署（SSH 密钥由教师持有） | 教师 |

> 如果某个按钮是灰的或提示无权限，先对照这张表看自己缺哪一层，再找组长/教师，不要反复点击。

## 2 开始之前

### 2.1 准备清单

| # | 准备项 | 完成标准 | 卡住找谁 |
| --- | --- | --- | --- |
| 1 | 手机号/邮箱可收验证码 | 能注册阿里云账号 | 自己 |
| 2 | 阿里云账号已实名（部分云效功能需要） | 账号中心显示已实名 | 教师 |
| 3 | 收到组织邀请链接 | 打开链接能申请加入 | 教师 |
| 4 | 知道自己组号与角色 | 分组表上有你的名字 | 组长 |
| 5 | 本机有 Git、浏览器（Chrome/Edge） | `git --version` 正常 | 自己 |
| 6 | 项目代码已在本地可运行（第 1 次课任务） | 三端能起、`/api/ping` 返回 code=0 | 组内后端 |

### 2.2 注册并登录阿里云 / 云效

**做什么**：拥有一个能登录云效的账号。

**操作**
1. 浏览器打开阿里云官网，点右上角「登录/注册」，用手机号或邮箱注册。
2. 登录后按提示完成实名认证（个人认证即可；需要企业认证的功能本课程不用）。
3. 在阿里云控制台搜索「云效」，进入云效控制台；或在浏览器地址栏输入云效帮助中心里的控制台入口。
4. 若提示「尚未加入组织」，说明邀请链接还没生效，先做 2.3。

**预期**：能进入云效控制台，页面出现「工作台/组织」等入口。

**失败怎么办**
- 收不到验证码：检查手机号是否被运营商拦截、是否今日发送次数超限，换邮箱注册。
- 实名认证失败：多为姓名与身份证不一致，按提示重新拍证件。

✅ **检查点**：云效控制台首页截图（能看到你的头像/昵称）。

### 2.3 加入组织

**做什么**：成为课程云效组织的一员。

**操作**
1. 打开教师发的**邀请链接**（或邀请码）。
2. 页面提示「加入组织」时，确认组织名是教师指定的课程组织名，点「加入/申请加入」。
3. 若需要审批，等教师在组织成员里通过；期间可先做 2.5。
4. 加入后在「组织管理 → 成员」里能看到自己的姓名与工号/学号信息。

**预期**：组织成员列表出现你的名字；能进入组织内的项目列表。

**失败怎么办**
- 链接过期：找教师要新链接；不要重复注册账号。
- 加入后看不到项目：项目还没把你加为成员，让组长按 3.1 最后一步添加成员。
- 用微信/钉钉扫码登录导致出现两个账号：统一用一个登录方式，把另一个退出。

✅ **检查点**：组织成员列表截图（含你的名字与所在组）。

### 2.4 关键占位符从哪里拿（重点）

课程材料里会出现 `<代码库地址>`、`<服务连接 ID>`、`<主机组 ID>` 这类占位符。它们不是让你猜，按下面的表拿（`deploy/flow/campus-activity-pipeline.yaml` 里用的是尖括号英文名，两套写法是同一个东西）：

| 占位符 | YAML 里的写法 | 什么时候用 | 从哪拿 | 拿到的样子（示例） |
| --- | --- | --- | --- | --- |
| `<代码库地址>` | `<CODEUP_REPO_URL>` | 克隆代码、配置流水线源 | Codeup → 你的代码库 → 右上「克隆/下载」，复制 **HTTPS** 地址 | `https://codeup.aliyun.com/<组织ID>/campus-activity-01.git` |
| `<代码库名>` | `<REPO_NAME>` | YAML 代码源的展示名称 | Codeup 代码库列表里的库名 | `campus-activity-01` |
| `<服务连接 ID>` | `<SERVICE_CONNECTION_ID>` | 流水线拉取代码、部署时鉴权 | Flow → 流水线 → 代码源/部署配置里选择「服务连接」；没有时由教师创建并共享，在服务连接列表看 ID/名称 | `flow-service-connection-xxxx` |
| `<主机组 ID>` | `<MACHINE_GROUP_ID>` | 主机部署任务选择目标机器 | Flow → 主机组 → 点进主机组，详情页有主机组 ID | `host-group-xxxx` |
| `<ECS 公网 IP>` | — | 部署后验证、答辩演示 | 阿里云 ECS 控制台实例详情（教师提供） | `47.xx.xx.xx` |
| `<组号>` | — | 项目名、代码库名、部署路径 | 分组表 | `01` |
| `<任务号>` | — | 分支名、MR 标题 | Projex 任务详情页左上角编号 | `CA-12` |

**规则**：这些值只在组内共享，**不要**发到公开群、不要写进代码仓库、不要写进 README 提交。教师只把主机组访问权授给组长与 DevOps。

**失败怎么办**
- 代码库地址复制成 SSH 形式却不会配密钥：第 1 次课统一用 HTTPS + 账号密码/个人访问令牌。
- 看不到服务连接/主机组：说明还没共享给你，让教师或组长在对应产品里添加成员权限。

✅ **检查点**：把上表占位符的真实值填进你们组的「云效速查卡」（一个共享文档或项目 README，**不写密码**）。

## 3 项目协作 Projex

> 本章对应第 1 次课「云效立项」与全程的看板/缺陷操作。每一步都有 ✅ 检查点，检查点就是评分证据。

### 3.1 新建项目（Scrum 模板）

**做什么**：为你们组建一个带迭代、需求、任务、缺陷、看板的项目。

**操作**
1. 顶部导航进入「项目」→「新建项目」（或「新建」→「项目」）。
2. 模板选 **Scrum**（有的界面叫「敏捷研发」「Scrum 项目」）。
3. 项目名称填 `CA-<组号>-校园活动`（严格按格式，评分按名称找项目）。
4. 可见范围选「组织内可见」或「私有」，课程建议私有 + 组员可见。
5. 创建后进入项目设置 → 成员，把全组同学加为成员（组长为项目管理员）。
6. 在项目描述里写三行：组号、组员名单与角色、项目一句话目标。

**预期**：项目列表出现 `CA-01-校园活动`；组员都能打开项目。

**失败怎么办**
- 没有「新建项目」按钮：你的组织角色不足，找教师建好后转交，或让教师把你设为项目创建者。
- 项目名重复：说明组号填错或有人已建，先问组长，不要建第二个。
- 成员加不进去：确认对方已加入云效组织。

✅ **检查点**：项目首页截图（项目名 + 成员头像）+ 项目描述三行文字。

### 3.2 建迭代 Sprint 1 / Sprint 2

**做什么**：把 4 次课切成两个时间盒。

**操作**
1. 项目 → 左侧「迭代」→「新建迭代」。
2. 名称填 `Sprint 1`，起止日期覆盖第 1、2 次课（例如本周周一至下次课当天），目标写「后端主链路跑通 + 24 条任务建齐」。
3. 再建 `Sprint 2`，覆盖第 3、4 次课，目标写「双端联调 + 测试 + 部署上线」。
4. 把「未规划」任务拖入对应迭代（或建任务时直接选迭代）。

**预期**：迭代列表有 2 个迭代，状态为「进行中/未开始」。

**失败怎么办**
- 建迭代按钮灰：Scrum 模板才有迭代，检查项目模板是不是选错成「看板项目」。
- 日期超出项目周期：项目设置里调整项目起止时间。

✅ **检查点**：迭代列表截图（2 个迭代 + 日期 + 目标）。

### 3.3 录入需求（≥24 条需求/任务的总入口）

**做什么**：把「校园活动小程序」拆成可执行的需求清单。

**操作**
1. 项目 →「需求」→「新建需求」。
2. 标题写「用户故事」句式：`作为学生，我希望看到活动列表，以便决定报名哪个`。
3. 描述写 3 段：背景、验收标准（可测）、关联的项目文档章节（如 `02-需求规格说明书 §4`）。
4. 优先级 P0/P1/P2；P0 = 主链路（登录、活动、报名、签到）。
5. 建议先建 8–10 条高层需求（学生端/组织者端/管理端/系统支撑），再在其下拆任务。

**参考需求清单**（可直接照抄改）：

| 需求 | 角色 | 验收标准（简） | 优先级 |
| --- | --- | --- | --- |
| 学生登录与学号绑定 | 学生 | 登录成功 → 绑定 2023001 → 进入首页 | P0 |
| 活动分类与列表 | 学生 | 6 个分类；列表可分页/筛选 | P0 |
| 活动详情与报名 | 学生 | 名额进度正确；报名成功可在「我的报名」看到 | P0 |
| 满员候补 | 学生 | 满员后报名进入候补；取消后自动转正 | P0 |
| 扫码签到 | 学生 | 签到码有效；重复签到被拦截 | P0 |
| 我的报名与消息 | 学生 | 状态正确；消息列表可见 | P1 |
| 组织者发布/编辑活动 | 组织者 | 保存草稿 → 提交审核 | P0 |
| 组织者报名名单与核销 | 组织者 | 名单可导出；补签有记录 | P0 |
| 后台审核与下架 | 管理员 | 审核通过后学生可见 | P0 |
| 用户、组织、操作日志管理 | 管理员 | 分页查询、角色变更留日志 | P1 |
| 短信验证码登录 | 学生 | Mock 验证码可登录；60 秒重发限制 | P0 |
| 文件上传（活动封面/头像） | 组织者 | 上传后返回 `/uploads/...` 可访问 | P1 |

✅ **检查点**：需求列表 ≥10 条，每条有优先级和验收标准。

### 3.4 把需求拆成任务（≥24 条，必做）

**做什么**：任务粒度 ≤1 人天，任务必须关联需求，且有负责人、工时、验收标准。

**操作**
1. 需求详情页 →「拆解任务」或项目 →「任务」→「新建任务」。
2. 标题用动词开头：`实现活动列表接口`、`完成 H5 活动详情页`。
3. 必填五项：关联需求、负责人、计划工时（0.5/1/2 天）、迭代、验收标准。
4. 描述里写：要改哪些文件/目录、怎么自测（命令或页面路径）、提交物（截图/MR 链接）。
5. 全部建完后数一遍：**≥24 条**；不够就继续拆（前端每个页面、后端每个接口都能拆）。

**24 条任务的标准分法**（教师可直接发）：

| 模块 | 条数 | 任务示例 | 负责角色 |
| --- | --- | --- | --- |
| 环境与工程基础 | 4 | 建库导数据 / 后端编译启动 / 三端启动脚本 / README 复现步骤 | 后端 + 全员 |
| 认证与用户 | 4 | JWT 登录 / 学号绑定 / 后台登录 / 登出黑名单 | 后端 |
| 活动 | 5 | 分类与列表 / 详情 / 发布活动 / 提审 / 审核与下架 | 后端 + 前端 |
| 报名与签到 | 5 | 报名 / 满员候补 / 取消报名 / 签到码 / 扫码与补签 | 后端 + 测试 |
| 前端双端 | 4 | H5 首页列表详情 / 我的报名 / 后台审核页 / 素材上传页 | 前端 |
| 测试与部署 | 2 | 冒烟脚本执行与记录 / 流水线配置 | 测试 + DevOps |

**失败怎么办**
- 不知道怎么拆：按「一个接口一个任务、一个页面一个任务」拆，最保险。
- 任务关联不到需求：先在需求详情里建关联，或在任务详情里手动关联。

✅ **检查点**：任务列表 24 条 + 每条有负责人；截图交给教师。检查点标准：任务有迭代、有负责人、有关联需求。

### 3.5 缺陷录入与流转（≥8 条）

**做什么**：把「发现的问题」变成可跟踪、可验收的缺陷单。

**操作**
1. 项目 →「缺陷」→「新建缺陷」。
2. 标题：`[模块] 现象`，如 `[报名] 满员后报名提示 500 而非「名额已满」`。
3. 必填：复现步骤（1/2/3）、期望结果、实际结果、严重程度（致命/严重/一般/轻微）、指派给谁。
4. 修复后：开发把状态改为「已解决」，测试回归通过后改「已关闭」；回归不通过打回「重新打开」。
5. 一次课至少建 8 条（教师会发缺陷场景卡，也可从联调中真实发现）。

**8 条缺陷预案参考**（教师可用于缺陷狩猎赛）：

| # | 模块 | 缺陷 | 期望 |
| --- | --- | --- | --- |
| 1 | 报名 | 重复点击报名两次 | 第二次提示「已报名」，不产生两条记录 |
| 2 | 报名 | 名额满后报名 | 进入候补或提示 30001，不报 500 |
| 3 | 签到 | 用过期签到码 | 提示 40001，不签到成功 |
| 4 | 签到 | 同一活动重复签到 | 提示 40003「已签到」 |
| 5 | 审核 | 组织者调用后台审核接口 | 返回 403/10002 |
| 6 | 上传 | 上传伪装成 .png 的文本 | 返回 70003，不落盘 |
| 7 | 短信 | 60 秒内连续发码 | 返回 60002 |
| 8 | 登出 | 登出后旧 token 再访问 | 401/10001 |

✅ **检查点**：缺陷列表 ≥8 条，状态有流转记录（至少 1 条走到「已关闭」）。

### 3.6 看板使用（每天必须更新）

**做什么**：让全组和教师一眼看到进度。

**操作**
1. 项目 →「看板」（Scrum 项目通常是「任务看板/迭代看板」）。
2. 看板列通常为：未开始 / 进行中 / 已完成（有的含「待验收」）。
3. 站会时逐张卡片拖动，不要事后补录。
4. 卡片上要能看到：标题、负责人、迭代、工时、优先级。
5. 每次课结束前，把已完成的任务拖到「已完成」并确认关联的需求状态。

**预期**：看板上每张卡片都有负责人；「进行中」≤ 人数（每人最多 1–2 张同时进行）。

**失败怎么办**
- 拖动无效：看板列与任务状态映射没配好，用任务详情改状态再看。
- 卡片太多看不清：按模块筛选，或给任务打标签（后端/前端/测试）。

✅ **检查点**：看板截图（每列卡片数 + 负责人头像），每次课末一张。

### 3.7 每日站会记录

**做什么**：每天留一条 90 秒站会的文字记录，作为过程分证据。

**操作**
1. 站会由组长主持，每人回答三问：昨天完成（对应任务号）、今天计划、有无阻塞。
2. 组长在迭代详情页「站会/纪要」写一条，或选中一个任务在评论里记录；没有专门入口时用「项目文档/ Wiki」建《站会记录》页。
3. 记录格式固定：

```
【站会】2026-11-11
- 张三（后端）：完成 CA-05 活动列表接口；今日 CA-06 详情接口；阻塞：无
- 李四（前端）：完成 CA-12 首页；今日 CA-13 列表页；阻塞：等后端联调数据
```

4. 阻塞项后面写「跟进人 + 预计解决时间」。

✅ **检查点**：站会记录 ≥4 条（每次课至少 1 条）。

### 3.8 批量导入、工时与燃尽（进阶）

| 功能 | 用法 | 注意 |
| --- | --- | --- |
| 批量导入任务 | 项目 → 任务 → 导入（Excel/CSV 模板） | 先下载模板，列名别改；导入后抽查 3 条 |
| 工时登记 | 任务详情 → 登记工时 | 每人每天 ≤8 小时，别为凑数乱填 |
| 燃尽图 | 迭代 → 燃尽图 | 第 2 次课起看趋势，不追求完美 |
| 筛选与保存视图 | 任务列表 → 筛选（负责人/迭代/状态） | 保存「我的任务」视图，站会前打开 |

**失败怎么办**：导入报错通常是有必填列空着或日期格式不对，逐行对照模板；导入重复时删除再导。

## 4 代码管理 Codeup

> 本章对应第 1 次课「建代码库 + 首次 MR」、第 2 次课「评审」、第 4 次课「tag 发布」。

### 4.1 新建/导入代码库

**做什么**：得到一个属于你们组的代码库 `campus-activity-<组号>`。

**操作（方式 A：从教师模板导入，推荐）**
1. 顶部导航「代码」→「新建代码库」→ 选「导入代码库」或「Fork」教师给的模板库。
2. 名称填 `campus-activity-<组号>`；路径自动生成，保持默认。
3. 可见性选「私有」；初始化选项不要勾「添加 README」（模板里已有）。
4. 创建后进入「设置 → 成员」，把全组加为开发者。

**操作（方式 B：本地已拷到项目）**
1. 新建空代码库 `campus-activity-<组号>`（不要初始化文件）。
2. 本地执行：

```bash
cd campus-activity
git init
git add .
git commit -m "chore: 初始化项目骨架"
git remote add origin <代码库地址>
git branch -M main
git push -u origin main
```

**预期**：代码库首页能看到 `server/ app/ admin/ docs/ deploy/` 等目录。

**失败怎么办**
- push 被拒（protected branch）：先推 `develop`，或用 `git push -u origin main` 且确认自己不是往保护分支直推；首次空库一般允许初始化推送。
- 大文件报错：`target/`、`node_modules/` 不应提交，检查 `.gitignore`。
- 历史提交里含密码：立刻改密码 + 用新提交覆盖（本课程不允许用 `filter-branch` 这种高风险操作）。

✅ **检查点**：代码库首页截图（库名 + 目录结构 + 最近提交）。

### 4.2 克隆与日常同步

```bash
# 克隆（HTTPS，<代码库地址> 按 2.4 节获取）
git clone <代码库地址>
cd campus-activity-<组号>

# 每天开工前同步
git checkout develop
git pull origin develop

# 建任务分支
git checkout -b feat/CA-12-activity-list
```

| 场景 | 命令 | 说明 |
| --- | --- | --- |
| 看当前分支 | `git branch --show-current` | 提交前确认不在 `main` |
| 看改动 | `git status` + `git diff` | 提交前自查，不要把调试代码带上 |
| 暂存部分改动 | `git add <文件>` | 不要无脑 `git add .` |
| 提交 | `git commit -m "feat(app): 完成活动列表页"` | 见 4.5 提交规范 |

**失败怎么办**
- HTTPS 每次要密码：配置个人访问令牌（Codeup 个人设置 → 访问令牌），或在凭据管理器里保存。
- `git pull` 冲突：先 `git stash`，拉取后再 `git stash pop`；冲突文件按现场处理，别直接删。

### 4.3 分支规范与创建

| 分支 | 命名 | 从哪建 | 用途 | 谁能推 |
| --- | --- | --- | --- | --- |
| `main` | 固定 | 初始 | 可演示稳定版本 | 无人（保护） |
| `develop` | 固定 | `main` | 集成分支 | 无人（保护） |
| 功能分支 | `feat/<任务号>-<简述>` | `develop` | 一个任务一个分支 | 作者 |
| 缺陷分支 | `fix/<缺陷号>-<简述>` | `develop` | 一个缺陷一个分支 | 作者 |
| 教程回放分支 | `tutorial/from-zero` | 教师/仓库自带 | 从零构建 65 提交回放（只读，见 4.10） | 无人（保护） |

命名示例：`feat/CA-12-activity-list`、`feat/CA-18-signup-waitlist`、`fix/CA-31-checkin-code-expired`。任务号就是 Projex 任务详情里的编号前缀。

**操作**
1. 代码库 →「分支」→「新建分支」：源分支选 `develop`，名称按规范。
2. 或本地 `git checkout -b feat/CA-12-activity-list develop` 后 push。
3. 分支生命周期 ≤3 天，合并后删掉。

**失败怎么办**
- 分支名不合规：改名（本地 `git branch -m`，远端删旧建新）。
- 建分支时选错源：删除重建，别在错误基础上提 MR。

✅ **检查点**：分支列表截图（含至少 1 个 `feat/CA-*` 分支）。

### 4.4 保护分支与 MR 卡点（组长/DevOps 操作）

**做什么**：防止误推 `main`/`develop` 覆盖代码，并让「改完必须评审、检查通过才能合」成为平台规则，而不是靠自觉。

**操作（入口）**：代码库 → 左侧「设置」→「分支设置」→ 右上「+ 新建保护分支规则」。

**推荐规则（照这张表填，`main` / `develop` 各建一条）**

| 配置项 | `main` | `develop` | `tutorial/*`（仓库自带教程分支时） |
| --- | --- | --- | --- |
| 分支规则 | `main` | `develop` | `tutorial/*`（通配符） |
| 允许推送的角色 / 人员 | 不选任何角色、不填人员＝**不允许任何人直推** | 同左 | 同左 |
| 允许合并的角色 / 人员 | 管理者 + 开发者 | 管理者 + 开发者 | 不选＝只读 |
| 最少评审通过人数 | 1 | 1 | — |
| 允许创建者通过 | 否（必须别人评审） | 否 | — |
| 评论已全部解决 | 是 | 是 | — |
| 要求合并前通过自动化状态检查 | 开（见下「MR 卡点」） | 可先不开，第 4 次课再开 | — |

新建规则时平台默认「允许推送 / 允许合并」都是管理者 + 开发者；**推送规则必须逐个取消勾选**，才是「谁都不能直推」。保护分支同时限制删除和强制推送。

**MR 卡点（合并前自动化检查）怎么配**
1. 先有检查来源，二选一：
   - Codeup「代码检测」：代码库 → 代码检测 → 新建任务（默认规则即可）；
   - Flow「流水线检测」：先按第 5 章创建/关联流水线，并按 5.2 打开「代码源触发 → 代码提交」（否则流水线不会自动跑，卡点永远不通过）。
2. 分支设置 → 打开 `main` 的规则 → 合并规则 → 打开「要求合并前通过自动化状态检查」→ 勾选「代码检测任务」或「流水线检测」→ 选中具体任务/流水线 → 保存。
3. 课程建议：第 3–4 次课流水线跑绿后再给 `main` 挂卡点；`develop` 先只卡「评审 1 人」，避免全组被 CI 阻塞。

**验证（两人配合，10 分钟）**
- 组员本地 `git push origin main` → 终端提示 `protected branch` 或被拒绝 ✅
- 组员 `git push origin develop` → 同样被拒，只能走 MR ✅
- 开一个测试 MR（`feat/CA-xx-test` → `develop`，先不合并）：没人 Approve 时「合并」按钮不可用；1 人通过后可合并 ✅
- 给 `main` 挂流水线卡点后，流水线未跑/失败时 `develop → main` 的 MR 不能合并 ✅

**失败怎么办**
- 找不到分支设置：只有库管理员可见；不是就让组长操作，组员看结果。
- 自己能点合并（没等评审）：说明「允许创建者通过」没关，或你的角色是「管理者」——按表改规则，别用管理员账号日常开发。
- 卡点一直不通过：流水线没勾「代码提交」触发，或选的流水线从没运行过；检查 5.2 / 5.9。
- 已经误推：用 MR revert 回退并群里说明，不要强推覆盖历史。

✅ **检查点**：分支设置页截图（`main`/`develop` 两条规则 + `main` 的自动化检查已勾选）+ 一次「直推被拒」的终端截图。

### 4.5 提交规范

格式：`type(scope): 描述`。类型与范围固定：

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| `feat` | 新功能 | `feat(server): 报名满员后进入候补队列` |
| `fix` | 缺陷修复 | `fix(app): 修复我的报名状态不刷新` |
| `docs` | 文档 | `docs: 补充部署手册环境变量表` |
| `refactor` | 重构 | `refactor(admin): 抽取活动状态字典` |
| `test` | 测试 | `test(scripts): 冒烟新增伪造签到码断言` |
| `chore` | 构建/依赖/配置 | `chore: 升级 uni-app 依赖版本` |

范围取值：`server`、`app`、`admin`、`scripts`、`docs`、`db`。

**规则**：一次提交只做一件事；不提交密码、构建产物、`node_modules`、个人配置；提交信息不用「update」「111」。

**失败怎么办**：提交信息写错且未 push：`git commit --amend` 修改；已 push 到自己的分支：可以 `--force-with-lease` 强推**自己未合并的分支**（保护分支禁止）。

✅ **检查点**：`git log --oneline -10` 输出截图，提交信息符合规范。

### 4.6 创建合并请求（MR）

**做什么**：让你的改动被同学评审后再合入 `develop`。

**操作**
1. 代码库 →「合并请求」→「新建合并请求」。
2. 源分支选你的 `feat/CA-12-...`，目标分支选 `develop`。
3. 标题：`[CA-12] 实现活动列表页`；描述必须写三段：

```
改了什么：新增活动列表页、分类筛选、分页
为什么：完成 CA-12（关联需求 FR-S-02）
怎么验证：本地启动 app 5174 → 首页点「全部活动」→ 切换分类 → 翻页
截图/命令：附 2 张截图
```

4. 指定评审人（组内至少 1 人，建议跨角色评审）。
5. 提交后把 MR 链接贴到任务评论里（形成追溯）。

**预期**：MR 页面显示「可合并/有待评审」；评审人收到通知。

**失败怎么办**
- 提示有冲突：本地 `git pull origin develop` 解决冲突后再推送。
- 提示缺少评审：先评审再合并，不要绕过保护规则。
- 目标分支选错：关闭 MR 重建。

✅ **检查点**：MR 列表截图（≥1 个已合并 MR，标题含任务号）。

### 4.7 代码评审

**做什么**：作为评审人给 MR 写有质量的意见。

**评审清单（8 条，按此逐条看）**

| # | 检查项 | 不合格示例 |
| --- | --- | --- |
| 1 | 接口路径/参数与 05 号接口文档一致 | 自己改了路径没改文档 |
| 2 | 没有新增未登记的错误码 | 返回 `{"code":9999}` |
| 3 | 没有调试代码（`System.out`、`console.log`） | 打印 token |
| 4 | 异常分支有用户可读提示 | 500 直接抛给前端 |
| 5 | 权限：该加 `@PreAuthorize` 的加了 | 后台接口学生能调 |
| 6 | 提交信息与 MR 描述规范、关联任务号 | 标题「修改」 |
| 7 | 前端类型没有大面积 `any`、没有硬编码端口 | 请求写 `localhost:8080` |
| 8 | 没有敏感信息（密码、密钥、真实手机号）入库 | 配置文件里写死密码 |

**操作**
1. 打开 MR →「变更/文件」逐个看 diff。
2. 在具体行上评论：指出问题 + 给建议 + 说明依据（文档章节/代码位置）。
3. 全部看完点「通过/Approve」，或「需要修改」并 @ 作者。
4. 只写「LGTM」「+1」不计入评审分——至少要有 1 条实质意见。

✅ **检查点**：评审记录截图（≥3 条实质评论，全组累计）。

### 4.8 合并、删除分支与冲突处理

| 动作 | 操作 | 规则 |
| --- | --- | --- |
| 合并 MR | MR 页「合并」 | 评审通过 + 无冲突；合并方式用「合并提交」或平台默认 |
| 删除分支 | MR 合并页勾「删除源分支」 | 合并后再删，避免丢改动 |
| 合到 main | 组长发 MR `develop` → `main`，里程碑时做 | 第 2/4 次课里程碑各 1 次 |
| 冲突处理 | 本地 `git pull origin develop` → 编辑冲突文件 → `git add` → `commit` → push | 冲突在自己分支解决，不带到 `develop` |

✅ **检查点**：`develop` 分支提交历史截图（能看到 MR 合并记录）。

### 4.9 打 tag `v1.0.0`

**做什么**：第 4 次课把可交付版本标记为 `v1.0.0`。

**操作**
1. 代码库 →「标签/Tag」→「新建标签」，名称 `v1.0.0`，目标分支 `main`，说明写「课程交付版本：三端跑通 + 流水线部署」。
2. 或命令行：

```bash
git checkout main
git pull origin main
git tag -a v1.0.0 -m "课程交付版本 v1.0.0"
git push origin v1.0.0
```

**预期**：标签列表出现 `v1.0.0`；Flow 发布记录可关联该 tag/流水线运行。

**失败怎么办**：tag 名重复（已存在）→ 确认是否别人已打过，不要覆盖；打错分支 → 删除 tag 重打（`git tag -d` + `git push origin :refs/tags/v1.0.0`）。

✅ **检查点**：tag 页截图 + 版本说明文字。

**操作**

## 5 流水线 Flow

> 本章对应第 4 次课。**你不需要从零写流水线**：先按 Java 模板创建并跑通，再对照 `deploy/flow/campus-activity-pipeline.yaml` 理解每个阶段；教师会给主机组与部署路径。

### 5.1 从 Java 模板创建流水线

**做什么**：建 `campus-activity-ci`，能自动跑测试、打包、传制品、部署。

**操作**
1. 顶部导航「流水线」→「新建流水线」。
2. 模板选择：搜索 **Java**（「Java 应用构建并部署到 ECS 主机」模板），点「使用模板」。
3. 流水线名称改成 `campus-activity-ci`（严格按此名，第 4 次课按名称验收）。
4. 进入编辑页，按 5.2–5.7 依次配置源、构建、制品、部署。
5. 点「保存并运行」，先手动跑一次。

**预期**：流水线列表出现 `campus-activity-ci`；运行历史有 1 条记录。

**失败怎么办**
- 没有新建权限：让组长或教师建好后把成员加进流水线。
- 模板找不到：用「空流水线」手动加阶段，步骤与 5.3–5.7 相同。

✅ **检查点**：流水线列表截图（名称 + 最近一次状态）。

### 5.2 配置流水线源（Codeup）

**操作**
1. 流水线编辑页 →「流水线源 / 代码源」→ 选择「Codeup」。
2. 选择服务连接（没有就由教师创建并共享，拿到 `<服务连接 ID>`）。
3. 选择代码库 `campus-activity-<组号>`，默认分支 `main` 或 `develop`（建议 `develop` 用于日常构建）。
4. 开启「代码源触发 → 代码提交」（可选，课程建议每天构建一次即可，避免额度浪费；**若要把流水线当 MR 卡点，必须开启**，见 4.4）。

**预期**：源配置显示代码库名 + 分支；保存后能「拉取代码」成功。

**失败怎么办**
- 服务连接无效：找教师确认服务连接是否授权到该代码库。
- 拉不到代码：检查分支名是否写错、代码库是否为空。

### 5.3 构建阶段：JDK21 + Maven（注意 `server` 子目录）

**关键事实**：本仓库后端在 `server/` 子目录，构建目录必须设成 `server`，否则找不到 `pom.xml`。

**操作**
1. 在构建任务里选构建环境：**JDK 21**（必须，项目要求 17+，实际锁 21）。
2. 构建命令按顺序：

```bash
mvn -B -DskipTests package        # 先保证能打包
mvn -B test                       # 跑 20 个用例（可选阶段）
```

3. 把「工作目录/构建目录」设为 `server`。
4. 构建完成后确认产物路径：`server/target/campus-activity-server-1.0.0.jar`。

**预期**：日志出现 `BUILD SUCCESS`，产物列表能看到 jar。

> 说明：云效公共构建集群默认没有 MySQL/Redis，`mvn test` 会失败。课程标准做法是**跳过测试阶段**（YAML 版 `test_stage` 的注释已写明），测试证据用本地 `mvn -o test`（20/20）+ Testhub 执行记录。

**失败怎么办**
- `No such file: pom.xml`：构建目录没设成 `server`。
- 编译报 JDK 版本错：构建环境不是 JDK21。
- 依赖下载失败：构建集群网络受限，让教师改用「本地构建 + 上传制品」降级方案（见 5.8）。
- 测试失败：先看是否本机 MySQL/Redis 依赖（第 2 次课的测试需要真实 MySQL/Redis），流水线测试阶段可先用 `-DskipTests` 打包，测试放在 Testhub/本地跑。

### 5.4 前端构建（Node 20，选配但推荐）

**操作**
1. 在构建阶段加一个「Node.js 构建」任务（或在同阶段加执行命令步骤，镜像选 Node 20）。
2. 构建命令：

```bash
# 小程序 H5
cd app && pnpm install --frozen-lockfile && VITE_BASE=/app/ pnpm build:h5

# 管理后台
cd admin && pnpm install --frozen-lockfile && pnpm build
```

3. 产物目录：`app/dist/build/h5/`、`admin/dist/`。

**失败怎么办**
- 云端拉不到 npm 依赖（常见）：改用**降级方案**——本地构建两端，把产物目录一起上传为制品（见 5.8 与 06 号手册）。
- `pnpm: command not found`：用 `corepack enable` 或 `npm i -g pnpm`。

### 5.5 制品上传

**做什么**：把 jar、前端静态资源、部署脚本打成可下载的制品，供主机部署使用。

**操作**
1. 构建阶段后加「制品上传」任务（模板里通常已有）。
2. 上传内容按部署包结构组织（与 07 号附录第 13 节一致）：

```
app.jar           # = campus-activity-server-1.0.0.jar
web/admin/**      # admin/dist
web/app/**        # app/dist/build/h5（用 VITE_BASE=/app/ 构建）
deploy.sh         # 部署脚本
```

> 压缩包根目录必须恰好是这 4 个条目，不要再套一层 `package/`。

3. 若用 Packages，把 `package.tgz` 推送到制品仓库；不用 Packages 时用 Flow 的公共制品存储即可（本课程默认）。

**预期**：制品列表能看到 `package.tgz`（或等价制品），大小合理（几十 MB 内含前端）。

**失败怎么办**
- 制品里没有前端：检查 Node 构建是否成功、拷贝路径是否写对。
- `deploy.sh` 没在包根目录：主机部署脚本会找不到，按 5.7 的路径调整。

### 5.6 主机组接入 ECS

**做什么**：让流水线能登录 ECS 并执行部署命令（由教师/DevOps 完成，全组共用教师给的主机组）。

**教师侧操作（学生了解即可）**
1. 阿里云 ECS 控制台确认实例运行、安全组放行 22/80。
2. Flow →「主机组」→「新建主机组」→ 添加主机（公网 IP + SSH 端口 22 + 用户名如 `root` 或 `campus`）。
3. 凭据用「SSH 密钥」（教师生成密钥对，公钥放 ECS `~/.ssh/authorized_keys`，私钥填入云效凭据）。
4. 保存后等主机状态变为「在线」。

**学生侧操作**
1. 在主机部署任务里选择教师提供的主机组（`<主机组 ID>`）。
2. 如果主机显示「离线」，先告诉教师，不要反复重试。

**失败怎么办**
- 主机离线：安全组没放行 22 / SSH 密钥不匹配 / 服务器关机。
- 权限不足：用 `campus` 用户部署需要在 `/opt/campus-activity` 有写权限（06 号手册已配置）。

✅ **检查点**：主机组详情截图（主机在线）。

### 5.7 主机部署配置

**做什么**：把制品下载到 ECS 并重启服务。

**操作**
1. 流水线加「主机部署」任务，选择主机组与部署路径：`/opt/campus-activity/package.tgz`。
2. 部署脚本（模板里填，与 07 号附录第 13 节一致）：

```bash
mkdir -p /opt/campus-activity
tar zxvf /opt/campus-activity/package.tgz -C /opt/campus-activity/
sh /opt/campus-activity/deploy.sh restart
```

3. 部署后加一个验证步骤：

```bash
curl -s http://127.0.0.1:8016/api/ping
# 期望 {"code":0,"message":"ok","data":{"service":"campus-activity","status":"up"}}
```

4. 保存并运行，观察日志。

**预期**：流水线变绿；ECS 上 `/opt/campus-activity/` 有 `app.jar`、`web/`、`logs/`、`uploads/`；Nginx 访问 `http://<ECS 公网 IP>/` 出现管理后台登录页，`/app/` 出现 H5 首页。

**失败怎么办**
- 解压失败/路径不对：确认制品名是 `package.tgz` 且根目录结构符合 5.5 节。
- 服务起不来（端口占用/环境变量缺失）：看 `/etc/campus-activity/env` 是否配好；`journalctl -u campus-activity -n 50` 看日志；细节见 06 号手册第 9 章。
- 502：Nginx 反代的 8016 没起来，先在服务器上 `curl 127.0.0.1:8016/api/ping` 排查。

✅ **检查点**：流水线运行详情截图（4 个阶段全绿）+ 公网 URL 打开截图。

### 5.8 YAML 流水线（进阶，对照理解）

课程仓库提供 YAML 版流水线 `deploy/flow/campus-activity-pipeline.yaml`（与 06 号手册、`deploy/` 资产配套）。它把界面上点出来的配置写成代码，便于复制到别组和下一届；**本课程只要求读懂结构 + 改对 4 个占位符**，不要求从零写 YAML。

**流水线结构（与仓库实际文件一致）**

| 阶段 stage | 任务 job | 步骤 step | 作用 |
| --- | --- | --- | --- |
| `test_stage` 单元测试 | `backend_test_job` | `JavaBuild`（JDK 21，`cd server && mvn -B test`） | 跑 20 个用例；**公共构建集群没有 MySQL/Redis，课堂默认在运行配置里跳过或删除本阶段** |
| `build_stage` 构建与制品 | `build_job`（同一 job 内共享工作空间） | `JavaBuild`：`cd server && mvn -B clean package -DskipTests` | 产出 `server/target/campus-activity-server-1.0.0.jar` |
| | | `NodeBuild`（Node 20）：`cd admin && pnpm run build` | 产出 `admin/dist` |
| | | `NodeBuild`（Node 20）：`cd app && VITE_BASE=/app/ pnpm run build:h5` | 产出 `app/dist/build/h5` |
| | | `Command`：整理 `app.jar` / `web/admin` / `web/app` / `deploy.sh` | 与 07 号附录第 13 节部署包结构一致 |
| | | `ArtifactUpload`（`flowPublic`）：上传 `app.jar`、`web`、`deploy.sh` | 供主机部署下载 |
| `deploy_stage` 主机部署 | `deploy_job` | `VMDeploy`：`machineGroup` + `artifactDownloadPath: /opt/campus-activity/package.tgz` + 部署脚本 | 解压到 `/opt/campus-activity/` 并执行 `deploy.sh restart` |

**需要替换的 4 个占位符**（与 2.4 节一一对应）：

| YAML 占位符 | 含义 | 到哪拿 |
| --- | --- | --- |
| `<REPO_NAME>` | 代码库展示名称 | Codeup 代码库列表，如 `campus-activity-01` |
| `<CODEUP_REPO_URL>` | Codeup 仓库 clone 地址（HTTPS） | 代码库右上「克隆/下载」 |
| `<SERVICE_CONNECTION_ID>` | 服务连接 ID（Codeup 代码源认证） | 云效「设置 → 服务连接」，由教师创建并共享 |
| `<MACHINE_GROUP_ID>` | ECS 主机组 ID | Flow → 主机组 → 主机组详情 |

**四个必须知道的坑**

| # | 坑 | 处理 |
| --- | --- | --- |
| 1 | 单元测试阶段在公共集群失败 | 公共集群无 MySQL/Redis；课堂跳过该阶段，测试用本地 `mvn -o test` + Testhub 结果作为证据 |
| 2 | 后端/前端构建分成两个 job，产物互相找不到 | 构建与打包必须放在**同一个 job**（step 之间共享工作空间） |
| 3 | H5 部署在 `/app/` 子路径时页面白屏 | 用 `VITE_BASE=/app/ pnpm run build:h5` 重新构建（`app/vite.config.ts` 已支持），否则 `index.html` 引用 `/assets/...` 会 404（见 06 号手册 6.2） |
| 4 | 主机部署失败 | 部署前 ECS 必须已执行 `deploy/init-server.sh`、`/etc/campus-activity/env` 已配置、主机组在线 |

**使用规则**
1. 打开仓库里的 YAML，搜 `<` 找到 4 个占位符，用 2.4 节的方法替换成真实值。
2. 云效 Flow 新建流水线时选择「YAML 流水线 / 导入 YAML」，粘贴或指定仓库路径。
3. 保存后先「手动运行」一次，再决定是否开启代码提交自动触发。
4. 语法以云效当前版本为准；字段名可能变化，报错时对照官方 [YAML 流水线](https://help.aliyun.com/zh/yunxiao/user-guide/yaml-preliminary-experience)。

**建议路径**：先用界面版 Java 模板跑通（5.1–5.7），再迁移 YAML；不要一上来就用 YAML 排错，成本高。

### 5.9 运行、失败排查与降级

| 现象 | 常见原因 | 排查顺序 |
| --- | --- | --- |
| 拉代码失败 | 服务连接/分支名/权限 | 看日志第一步 → 核对 5.2 → 找教师 |
| Maven 依赖下载失败 | 构建集群网络受限 | 换公共镜像源；或改「本地构建 + 上传制品」 |
| 测试阶段失败 | 测试依赖 MySQL/Redis | 了解项目测试依赖真实数据库；课程可先跳过测试阶段打包 |
| 前端构建失败 | Node 版本/依赖锁文件 | 固定 Node 20；`pnpm install --frozen-lockfile` 失败时先本地确认 |
| 主机部署失败 | 主机离线/权限/制品路径 | 主机组状态 → SSH 手工登录验证 → 制品结构 |
| 部署后 502 | 后端未起/配置缺 | 服务器上 `curl 127.0.0.1:8016/api/ping`、`journalctl` |
| 运行超时/排队 | 组织配额不足 | 避开高峰、合并运行次数；找教师 |

**降级方案（网络受限时）**

| 情况 | 降级做法 |
| --- | --- |
| 云端 Maven 拉不动依赖 | 本地 `mvn -o -DskipTests package` 出 jar，手工上传到制品，流水线只做部署阶段 |
| 云端 Node 拉不动依赖 | 本地 `pnpm build:h5`、`pnpm build` 后把两个 dist 目录上传为制品 |
| 主机组不可用 | 用 06 号手册的手工部署步骤（scp + ssh + `deploy.sh restart`），截图为证 |

### 5.10 发布 v1.0.0 与回滚

**操作**
1. 第 4 次课：代码库打 tag `v1.0.0`（见 4.9）。
2. Flow → 流水线 →「发布单/发布记录」→ 新建发布记录，关联本次成功的运行与 tag。
3. 发布说明写：版本内容、部署环境、验证结果（`/api/ping`、首页、上传）。
4. 回滚演练：`deploy.sh restart` 会把当前版本归档到 `releases/`；方式 B（预发目录）会保留运行中旧 jar，方式 A（云效默认 tar 解压）旧 jar 已被新包覆盖、需用 `releases/` 上一次快照回滚；回滚 = 用快照 jar 替换 `app.jar` 后重启。

**预期**：发布记录状态为「已发布」；回滚后 `/api/ping` 仍正常。

✅ **检查点**：发布记录截图 + tag 截图 + 回滚前后健康检查截图。

| 7 | 组织者发布活动 | 组织者身份 | 发布 → 上传封面 → 提交审核 | 活动状态=待审核 |
| 8 | 管理员审核通过 | 管理员登录 | 审核 → 通过 | 学生端可见 |
| 9 | 扫码签到 | 已报名 | 获取签到码 → 扫码 | 签到成功，状态更新 |
| 10 | 重复签到拦截 | 已签到 | 再扫一次 | 提示已签到（40003） |
| 11 | 短信验证码登录 | Mock 通道 | 13800000003 发码 → 登录 | 登录成功（mockCode 自动填入） |
| 12 | 退出登录后 token 失效 | 已登录 | 登出 → 用旧 token 请求 | 401/10001 |
| 13 | 文件上传访问 | 已登录 | 上传 PNG | 返回 `/uploads/...`，浏览器可访问 |
| 14 | 越权访问后台 | 学生 token | 调 `/api/admin/activities` | 403/10002 |

✅ **检查点**：用例列表 ≥12 条。

### 7.3 执行测试并记录结果

**操作**
1. 测试计划 →「执行」→ 逐条用例点「通过/失败/阻塞」，失败时填实际结果。
2. 把失败用例关联缺陷：执行结果里「创建缺陷」或在 Projex 手工建后回填缺陷编号。
3. 执行完看统计：通过率、失败数、阻塞数。

**预期**：计划进度 100%，通过率 ≥80%；失败项均有缺陷单号。

✅ **检查点**：执行结果统计页截图（通过/失败数量 + 关联缺陷）。

## 9 教师与组长管理技巧

### 9.1 成员与权限

| 场景 | 操作 |
| --- | --- |
| 加成员 | 项目设置 → 成员 → 添加（按学号/姓名搜索）→ 选角色（管理员/开发/测试） |
| 成员看不到流水线 | Flow 流水线 → 成员管理 → 添加为运行者/编辑者 |
| 成员不能推代码 | 代码库 → 设置 → 成员 → 开发者 |
| 转交项目 | 项目设置 → 成员 → 把组长设为管理员，原创建者保留 |
| 移出成员 | 每轮课结束后清理，避免下届误访问 |

### 9.2 模板库与模板项目

| 资产 | 教师准备 | 学生使用 |
| --- | --- | --- |
| 模板项目 | 24 条任务、2 个迭代、8 条缺陷预案、看板列 | 复制/导入后改名 `CA-<组号>-校园活动` |
| 模板代码库 | 三端代码 + `deploy/` 资产 + 保护分支已配 | Fork/导入后改名为 `campus-activity-<组号>` |
| 样例流水线 | `campus-activity-ci` 跑通过一次 | 复制后替换占位符 |
| 测试用例模板 | 12–14 条用例（7.2 节表格） | 导入 Testhub 后增补 |

### 9.3 批量建任务

1. 用 Excel/CSV 按 Projex 导入模板填：标题、类型、优先级、负责人、迭代、关联需求、工时。
2. 导入前抽查 3 行；导入后数总数 ≥24。
3. 常见错误：负责人写昵称（应为姓名/账号）、迭代名多空格、日期格式 `2026/11/11` 写成 `2026-11-11`。

### 9.4 评分数据导出

| 数据 | 导出方式 | 用途 |
| --- | --- | --- |
| 任务列表 | 项目 → 任务 → 导出 CSV | 统计完成率、负责人分布 |
| 迭代统计 | 迭代详情 → 导出/截图 | 过程分 |
| MR 列表 | 代码库 → 合并请求 → 筛选后截图 | 代码贡献分 |
| 流水线历史 | Flow → 运行历史 → 截图 | 部署分 |
| 测试执行 | Testhub → 计划 → 导出执行结果 | 质量分 |
| 成员工作量 | 工作台/任务工时统计 | 组内互评核对 |

> 课程结束前，教师统一保存「每组 1 个证据文件夹」（截图 + 导出 CSV + 公网 URL），作为成绩归档。

## 10 常见问题（FAQ）

| # | 问题 | 原因 | 解决 |
| --- | --- | --- | --- |
| 1 | 收不到短信/邮箱验证码，注册不了 | 运营商拦截、发送次数超限 | 换邮箱注册；等 10 分钟；联系教师统一处理 |
| 2 | 加入组织后看不到项目 | 不是项目成员 | 找组长在项目设置里添加；确认加入的是课程组织 |
| 3 | 登录后提示「无权限访问」 | 角色不足（如学生点后台） | 检查自己的角色；需要权限找组长/教师，不要重复尝试 |
| 4 | 点「新建项目/新建代码库」没有按钮 | 组织角色不足 | 由教师创建后转交，或请教师提升角色 |
| 5 | 代码 push 提示 protected branch | 保护分支禁止直接推送 | 建 `feat/*` 分支 → 提 MR → 评审合并 |
| 6 | 克隆代码要求输入密码，输账号密码不对 | 云效用个人访问令牌而非登录密码 | 代码库/个人设置里生成访问令牌，密码处填令牌 |
| 7 | MR 无法合并，提示冲突 | 目标分支已更新 | 本地 `git pull origin develop` 解决冲突后 push |
| 8 | MR 没人评审，合并不了 | 保护规则要求评审 | 指定组内评审人并提醒；组长可临时调整规则（记录原因） |
| 9 | 流水线拉代码失败 | 服务连接失效/分支写错/无权限 | 检查 5.2 配置；让教师确认服务连接授权 |
| 10 | Maven 依赖下载超时 | 构建集群网络受限 | 换镜像源；或本地构建后上传制品（降级） |
| 11 | 流水线构建报 `pom.xml` 不存在 | 构建目录没设 `server` | 工作目录改为 `server` 后重跑 |
| 12 | 主机组显示离线 | 安全组未放行 22 / 密钥不匹配 / ECS 关机 | 找教师检查 ECS 与主机组；不要反复重试 |
| 13 | 部署成功但打不开页面 | Nginx 未配置/后端未起/端口未放行 | 服务器上 `curl 127.0.0.1:8016/api/ping`；检查 Nginx 80；安全组放行 80 |
| 14 | 上传封面后图片 404 | 部署包没带 `web/` 或 Nginx 未配静态目录 | 检查制品结构；见 06 号手册 Nginx 配置 |
| 15 | 测试计划用例执行失败但本地正常 | 环境差异（数据/账号/端口） | 用 07 号事实清单的账号与数据；确认后端 8016 |
| 16 | 流水线排队很久/运行失败提示额度 | 组织配额/并发限制 | 错峰运行、减少自动触发；找教师 |
| 17 | 忘记密码/账号被锁 | 登录失败次数过多 | 走阿里云账号找回流程；教师协助 |
| 18 | 界面和你手册上说的不一样 | 云效版本更新 | 按功能找入口；以云效当前界面与官方文档为准 |

**遇到 FAQ 没有的问题**：先截图（含报错原文与 URL）→ 发到班级群「问题格式：现象 + 已试 + 期望」→ 5 分钟未解按课次文档找教师，不要一个人耗 20 分钟。

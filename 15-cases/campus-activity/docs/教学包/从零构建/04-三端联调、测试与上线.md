### 1.3 三端启动顺序与验证

启动顺序固定为 **MySQL/Redis → 后端 8016 → 小程序 H5 5174 → 管理后台 5173**；后端依赖中间件，两个前端依赖后端接口。

```bash
# ── 1) MySQL（已作为服务运行可跳过启动，直接验证） ──
mysqladmin -h127.0.0.1 -P3306 -uroot -p123456 ping
# 期望：mysqld is alive
# 首次需要建库导数据（唯一手工前置）：
mysql -uroot -p123456 -e "CREATE DATABASE IF NOT EXISTS campus_activity DEFAULT CHARSET utf8mb4"
cd server/src/main/resources/db
mysql -h127.0.0.1 -P3306 -uroot -p123456 campus_activity < schema.sql
mysql -h127.0.0.1 -P3306 -uroot -p123456 campus_activity < data.sql

# ── 2) Redis（database 11，密码 abc123） ──
redis-server --port 6379 --requirepass abc123 --daemonize yes   # 已服务化可跳过
redis-cli -a abc123 --no-auth-warning -n 11 ping                # 期望：PONG

# ── 3) 后端 8016（终端 1） ──
cd server
mvn -o spring-boot:run
# 期望日志：Tomcat started on port 8016 / Started CampusActivityApplication in x seconds
curl -s http://127.0.0.1:8016/api/ping
# 期望：{"code":0,"message":"ok","data":{"service":"campus-activity","status":"up"}}

# ── 4) 小程序 H5 5174（终端 2） ──
cd app
pnpm install
pnpm run dev:h5
# 期望：Local: http://localhost:5174/
# 端口被占用时 Vite 会自动换到 5175/5176，以终端输出为准

# ── 5) 管理后台 5173（终端 3） ──
cd admin
pnpm install
pnpm run dev
# 期望：Local: http://localhost:5173/
# 登录账号：admin / Admin@123
```

| 顺序 | 启动项 | 验证要点 | 常见失败 |
| --- | --- | --- | --- |
| 1 | MySQL 3306 | `mysqld is alive`；12 张表、`activity` 4 条演示数据 | 未建库/未导数据 → 后端登录 500；密码不对 → Access denied |
| 2 | Redis 6379 | `-n 11 ping` 返回 `PONG` | 未设密码/密码错 → 缓存、短信、登出全部报错 |
| 3 | 后端 8016 | `/api/ping` 返回 `code=0`；日志无 `ERROR` | 端口占用见第 6 章；依赖未起 → 启动慢/连接异常 |
| 4 | 小程序 H5 5174 | 浏览器打开首页能拉到分类/活动；Network 中 `/api` 走 Vite 代理 | 页面空白 → 后端未起或代理端口不对（应为 8016） |
| 5 | 管理后台 5173 | 打开登录页，`admin / Admin@123` 能登录 | 登录 401 → 后端未起/账号密码错 |

> **关闭顺序与启动相反**：后端 → MySQL/Redis（或保留服务）。前端 dev server 直接 `Ctrl+C`。

### 2.2 C1：后端可编译、可启动（`ba086b2`）

```bash
git checkout ba086b2

# 期望日志（关键行）：
#   Tomcat started on port 8016
#   Started CampusActivityApplication in x.xxx seconds
```

**⚠️ 诚实说明（很重要）**：C1 提交时 `SecurityConfig` 还没有提交（它在 B15 `9588660` 才出现），而 `spring-boot-starter-security` 在 B01 就已进入 `pom.xml`。此时 Spring Boot 的**默认安全**会给所有请求加认证，`curl /api/ping` 返回 **401**，这不是代码错误。要看到 `code=0` 的 `/api/ping`，请 `git checkout ee173f6`（C2）及之后的提交；C1 的「可启动」以启动日志与 8016 端口监听为准。

```bash
# C2 及之后验证 ping
curl -s http://127.0.0.1:8016/api/ping
# 期望：{"code":0,"message":"ok","data":{"service":"campus-activity","status":"up"}}
```

| 失败现象 | 原因 | 处理 |
| --- | --- | --- |
| `release version 21 not supported` | Maven 用了 JDK 17/其他 | `mvn -v` 确认 Java 21；配置 `JAVA_HOME` |
| `Port 8016 was already in use` | 旧后端未退出 | `lsof -iTCP:8016 -sTCP:LISTEN` 找到 PID 后 `kill -15` |
| `curl /api/ping` 返回 401 | C1 阶段默认安全（见上） | checkout C2 再验；不是缺陷 |
| 编译下载依赖失败 | 本机仓库未缓存，`-o` 离线失败 | 首次去掉 `-o` 联网下载 |

✅ **检查点 C1**：`mvn -o -DskipTests compile` → BUILD SUCCESS + 启动日志出现 `Started CampusActivityApplication`。

### 2.3 C2：登录拿 token（`ee173f6`）

```bash
git checkout ee173f6
cd server && mvn -o spring-boot:run        # 需要 MySQL 可用，且已导入 12 张表 + data.sql
```

> 下面用 `jq` 取 token；未安装 jq 时先装（macOS `brew install jq`，Ubuntu `apt install jq`），或手工复制 token。

```bash
# 1) dev 模式登录（application.yml 默认 campus.dev-mode=true）
curl -s -X POST http://127.0.0.1:8016/api/app/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"devOpenId":"mock-student-1"}'
# 期望：code=0；data.token 有值；data.user.nickname=张小明；role=STUDENT
# 刚导入 data.sql 时 needBind=true（未绑学号）；跑过 smoke 或绑定后 needBind=false

# 2) 取 token 并访问个人资料
TOKEN=$(curl -s -X POST http://127.0.0.1:8016/api/app/auth/login \
  -H 'Content-Type: application/json' -d '{"devOpenId":"mock-student-1"}' | jq -r '.data.token')
curl -s http://127.0.0.1:8016/api/app/user/profile -H "Authorization: Bearer $TOKEN"
# 期望：code=0；data.nickname=张小明；data.bound=true（绑定后）

# 3) 绑定学号（未绑定时）
curl -s -X POST http://127.0.0.1:8016/api/app/auth/bind \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"studentNo":"2023001","realName":"张小明"}'
# 期望：code=0；data.studentNo=2023001；data.bound=true

# 4) 后台账号登录
curl -s -X POST http://127.0.0.1:8016/api/admin/auth/login \
  -H 'Content-Type: application/json' -d '{"username":"admin","password":"Admin@123"}'
# 期望：code=0；data.user.role=ADMIN

# 5) 未带 token 访问受保护接口
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8016/api/app/user/profile
# 期望：401；响应体 {"code":10001,...}
```

| 失败现象 | 原因 | 处理 |
| --- | --- | --- |
| 登录返回 `code=10007` | 后台账号密码错 | 用 `admin / Admin@123`（种子数据） |
| 登录 500 / `Access denied` | 未建库/未导入 `data.sql`，或 MySQL 未启动 | 回到 1.3 第 1 步 |
| `需要登录` / 401 | 未加 `Authorization: Bearer <token>` 或 token 过期（2 小时） | 重新登录取 token |
| 绑定 `code=10004` | 学号不在白名单 | 用 2023001/2023002/2023003/2024001/2024002 |
| 绑定 `code=10005` | 学号已被其他微信绑定 | 换号，或在开发库重导 `data.sql` |

✅ **检查点 C2**：dev 登录 `code=0` 且有 token，token 能访问 `profile`，后台账号能登录，未带 token 返回 401/10001。

| `main` | 从 `develop` 合并 | 发布分支，配合 tag `v1.0.0` | 保护，只允许 MR |

```bash

# 开发完成后：push feat → 提 MR 到 develop → 至少 1 人评审 → 合并
```

### 5.3 云效 Flow 流水线

课程统一命名 `campus-activity-ci`，结构与仓库 [`deploy/flow/campus-activity-pipeline.yaml`](../../../deploy/flow/campus-activity-pipeline.yaml) 一致（4 个占位符：`<REPO_NAME>`、`<CODEUP_REPO_URL>`、`<SERVICE_CONNECTION_ID>`、`<MACHINE_GROUP_ID>`）。界面创建与排错见 05 手册第 5 章、06 手册 §7。

| 环节 | 关键配置 | 说明 |
| --- | --- | --- |
| 流水线源 | Codeup 服务连接 + `main`/`develop` 分支 | 服务连接 ID 由教师创建并共享 |
| 测试（可选） | `cd server && mvn -B test` | 公共构建集群无 MySQL/Redis，**课堂跳过**该阶段；测试证据用本地 20/20 + Testhub |
| 构建 | JDK 21 Maven（**构建目录 `server`**，不是仓库根）；Node 20 构建 `admin`、`app` | `mvn -B clean package -DskipTests`；H5 要 `/app/` 部署则带 `VITE_BASE=/app/` |
| 制品上传 | `app.jar`、`web/`、`deploy.sh` | 压缩包根目录恰好 4 个条目（app.jar、web/admin、web/app、deploy.sh） |
| 主机部署 | `VMDeploy` 组件：主机组 + 下载路径 `/opt/campus-activity/package.tgz` + 部署脚本 | 脚本见 5.4；命令级细节 06 §7.6 |

> 两个最常见的坑：① 构建与制品上传必须在**同一个 job**（不同 job 工作空间隔离）；② 后端在 `server/` 子目录，构建目录漏设会报 `pom.xml` 找不到。

### 5.4 主机部署与制品结构

云效主机部署时把制品下载为 `/opt/campus-activity/package.tgz`，执行脚本（与 07 号附录第 13 节、06 手册一致）：

```bash
mkdir -p /opt/campus-activity
tar zxvf /opt/campus-activity/package.tgz -C /opt/campus-activity/
sh /opt/campus-activity/deploy.sh restart
```

| 制品根目录 | 来源 |
| --- | --- |
| `app.jar` | `server/target/campus-activity-server-1.0.0.jar` |
| `web/admin/**` | `admin/dist` |
| `web/app/**` | `app/dist/build/h5` |
| `deploy.sh` | `deploy/deploy.sh` |

`deploy.sh restart` 负责：归档当前 jar 到 `releases/`（方式 B 预发目录可保留运行中旧 jar）→ 同步 `web/` → `systemctl restart campus-activity` → 轮询 `/api/ping` → `nginx -t && nginx -s reload`；失败非 0 退出（流水线变红）。部署前的一次性准备（init-server、`/etc/campus-activity/env`、Nginx 站点）见 06 第 3～6 章。

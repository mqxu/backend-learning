## 2 与后端轨道、后台轨道的并行关系

### 2.1 真实提交顺序：三轨交错，且“接口先就绪、页面再接”

教程分支的提交历史是**三轨交错**的，不是“后端全做完再做前端”。用 `git log` 可以验证：小程序 A01 是第 3 个提交、A11 是第 62 个，中间穿插着后端 B 与后台 D 的提交。

```text
S00 → B01 → A01 → D01 → B02 → A02 → D02
→ B03–B12（领域模型/C1）→ B13–B18（安全/C2）→ B19–B21（学生端活动接口）
→ A03（首页）→ D03（后台登录）→ B22–B23 → A04 → D04
→ B24–B26 → A05 → D05 → B27–B28 → A06 → D06 → B29–B30 → A07 → D07
→ B31–B36（Redis/短信）→ A08 → B37–B39（文件上传）→ A09 → D08 → A10 → D09(C5)
→ B40–B41(C3) → A11(C4) → S01–S03(C6)
```

排布原则：
1. **后端领域模型与安全先就绪**（B03–B18），前端脚手架和请求层同时起步（A01/A02、D01/D02）；
2. **页面用到哪个接口，就先有对应的后端提交**（例如 A03 首页排在 B21 之后、A10 上传封面排在 B39 之后）；
3. **同一个 45 分钟课堂里三轨可同时开**：后端组做 B 步、小程序组做 A 步、后台组做 D 步，按检查点汇合。

> 因此：跟做时不需要“等所有后端做完”；按上表顺序，做到某个 A 步时它依赖的 B 提交都已经在历史里了。若小组真正并行开发，则用 2.2 节的依赖表判断谁先合入。

### 3.2 为什么是这个顺序

1. **先地基后页面**：A01 工程能启动，A02 有类型与请求层，页面才不是“把 URL 硬编码进每个 .vue”。
2. **先学生后组织者**：学生链路（浏览→报名→签到）覆盖了绝大部分接口与生命周期写法；组织者页复用同样的分页、表单、上传模式。
3. **认证页夹在中间**：A05 报名会触发“未绑定/未登录”，所以 A06 紧接着补绑定与手机号登录。
4. **tabBar 必须等 4 个 tab 页齐全**：首页、列表、消息、我的都在 A07 才齐，因此 **`tabBar` 在 A07 的 `pages.json` 中首次出现**。

**关于“按已存在页面自动生成”**：

- uni-app 的 `pages.json` 是**手工维护的路由清单**，CLI 构建时**不会扫描** `src/pages/` 自动注册页面。只落 `.vue` 文件而不改 `pages.json`，页面打不开（编译期报找不到页面/运行时空路由）。
- HBuilderX 里“新建页面”会自动往 `pages.json` 写一项；本教程是“直接落文件”的方式，所以**每新增一个页面，都在同一个提交里手动追加一项**——这正是 A04–A11 每个提交都带 `pages.json` 修改的原因。
- `tabBar` 不是自动推导的：`list[].pagePath` 必须是 `pages` 里已注册的页面；4 个 tab 页齐全后才在 A07 一次性加入。

```ts
  if (!form.title.trim()) { uni.showToast({ title: '请填写活动标题', icon: 'none' }); return }
  if (!form.locationName.trim()) { uni.showToast({ title: '请填写活动地点', icon: 'none' }); return }

  const payload = {
    ...form,
    capacity: Number(capacityText.value) || 0,
    checkinType: checkinIndex.value + 1,
    startTime: `${startDate.value} ${startClock.value}:00`,
    endTime: `${endDate.value} ${endClock.value}:00`,
    signupStartTime: nowString(),
    signupEndTime: `${signupEndDate.value} ${signupEndClock.value}:00`
  }
  const data = await api.createActivity(payload)
  if (submitAfter) await api.submitActivity(data.id)   // toast 后 navigateBack 回工作台
}
```

**字段对应**：`POST /org/activities` body `SaveActivityPayload`（含 `coverUrl`、`startTime` 等全为字符串 `YYYY-MM-DD HH:mm:ss`）→ `{id}`；`POST /org/activities/{id}/submit`；`POST /files/upload?bizType=activity-cover`（multipart 字段 `file`）→ `FileUploadResult{objectKey,originalName,url,size,contentType,storage}`；封面渲染 `resolveFileUrl(form.coverUrl)`。

签到核销的轮换计时器：

```ts
const data = reactive<Partial<CheckinQr>>({})
const countdown = ref<number>(30)
let timer: ReturnType<typeof setInterval> | undefined

async function refresh(): Promise<void> {
  const res = await api.checkinQr(Number(activityId.value))
  Object.assign(data, res)
  countdown.value = res.refreshSeconds || 30
}
function startTimer(): void {
  if (timer) clearInterval(timer)
  timer = setInterval(() => {
    countdown.value -= 1
    if (countdown.value <= 0) refresh()
  }, 1000)
}
onLoad(async (options) => {
  activityId.value = Number(options?.id)
  await refresh()
  startTimer()
})
onUnload(() => { if (timer) clearInterval(timer) })
```

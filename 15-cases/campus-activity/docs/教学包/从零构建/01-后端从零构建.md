### 3.3 如何跟做与对比

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 看某一步改了什么 | `git show <sha>` | 完整 diff（文件、增删行） |
| 看某一步某文件内容 | `git show <sha>:<path>` | 该提交时刻的文件全文 |
| 只对比某个目录 | `git diff <sha> -- server/src/main/java` | 工作区与该提交的差异 |

### B02 统一响应体与全局异常（提交 96a5718e）

**目标**：定义全项目统一的 `Result<T>`、分页 `PageResult<T>`、错误码 `ResultCode`、业务异常 `BizException`、全局异常处理器 `GlobalExceptionHandler` 与时间工具 `DateTimes`。

**为什么现在做**：从 B12 起每个 Controller 都要返回 `Result`、每个 Service 都要 `throw new BizException(ResultCode.XXX)`；不先把“成功/失败/分页/时间格式”定下来，后面的接口会各写各的。

| 文件 | 作用 | 行数 |
| --- | --- | --- |
| `common/Result.java` | 统一响应 `{code,message,data}`，`ok/fail` 工厂方法 | 23 |
| `common/PageResult.java` | 分页响应 `{records,total,page,size}` | 25 |
| `common/ResultCode.java` | 错误码枚举（0/10xxx/20xxx/30xxx/40xxx/50xxx，后续扩展到 60xxx/70xxx） | 70 |
| `common/BizException.java` | 业务异常（携带 `code`），由全局处理器转 JSON | 23 |
| `common/GlobalExceptionHandler.java` | `@RestControllerAdvice`：业务异常 HTTP 200、校验 400、兜底 500 | 50 |
| `common/DateTimes.java` | `LocalDateTime` 与字符串互转（统一 `yyyy-MM-dd HH:mm:ss`） | 43 |

**关键代码**：`Result` 全文（后面所有 Controller 的返回类型）：

```java
package com.campus.activity.common;

/**
 * 统一响应体。code 为 0 表示成功，其余为业务错误码。
 */
public record Result<T>(int code, String message, T data) {

    public static <T> Result<T> ok(T data) {
        return new Result<>(0, "ok", data);
    }

    public static Result<Void> ok() {
        return new Result<>(0, "ok", null);
    }

    public static <T> Result<T> fail(int code, String message) {
        return new Result<>(code, message, null);
    }

    public static <T> Result<T> fail(ResultCode resultCode) {
        return new Result<>(resultCode.getCode(), resultCode.getMessage(), null);
    }
}
```


**命令与预期**：新建 `common/` 包并写入 6 个类；本步验证编译，并在 C1 后用接口观察响应结构。


**常见错误**：① 业务失败也返回 HTTP 500（前端会把“名额已满”当网络故障），本项目约定**业务异常 HTTP 200 + code**；② `Result` 用普通 class + Lombok 导致 Jackson 序列化字段顺序/空值不可控，这里用 `record`；③ `GlobalExceptionHandler` 没加 `@RestControllerAdvice`，异常会走默认错误页。

**检查点**：非检查点（随 C1 验证）。

### B03 登录用户上下文（提交 9a2a164e）

**目标**：定义 `LoginUser`（从 JWT 解析出的身份）与 `UserContext`（ThreadLocal 上下文），让 Controller/Service 用 `UserContext.requireUserId()` 取当前用户。

**为什么现在做**：B13–B15 的安全链会把身份写进这个上下文，B20 之后所有业务都读它；先定义接口，前后端模块才能各自推进。

| --- | --- | --- |
| `common/LoginUser.java` | `record(id, role, orgId, nickname)` + 角色判定便捷方法 | 28 |
| `common/UserContext.java` | ThreadLocal 读写、`requireUserId()`、`clear()` | 45 |

**关键代码**：`LoginUser` 全文（record 的访问器是 `id()`/`role()`，后面会反复用到）：

```java
package com.campus.activity.common;

/**
 * 从 JWT 解析出的登录身份。
 */
public record LoginUser(Long id, String role, Long orgId, String nickname) {

    public boolean isStudent() {
        return "STUDENT".equals(role);
    }

    public boolean isOrganizer() {
        return "ORGANIZER".equals(role);
    }

    public boolean isReviewer() {
        return "REVIEWER".equals(role);
    }

    public boolean isAdmin() {
        return "ADMIN".equals(role);
    }

    /** 组织者与管理员都可以管理活动 */
    public boolean canManageActivity() {
        return isOrganizer() || isReviewer() || isAdmin();
    }
}
```


**命令与预期**：新建两个类；本步验证编译，上下文行为在 B14 过滤器接入后由 C2 验证。


**常见错误**：① 用 `user.getId()` 取 id（record 没有 getter），编译报“找不到符号”；② ThreadLocal 只在过滤器里 `set` 不 `clear`，线程池复用会导致下一个请求串号（B14 会在 `finally` 清理）；③ 把 `LoginUser` 写成普通 class 却忘记 getter/构造器。

## 附录 C 常用 Git 速查（跟做必备）

```bash
git log --oneline tutorial/from-zero | grep backend        # 41 个后端提交
git show <sha> --stat                                       # 某步改了哪些文件
git show <sha>:<path>                                       # 某步某文件全文
git diff <sha> -- server/src/main/java/com/campus/activity  # 与教程某步的差异
git checkout <sha>                                          # 临时回放（建议先建自己的分支）
git switch -c my-backend && git checkout ba086b2            # 从 C1 开始自己敲
```

| 常见问题 | 解决 |
| --- | --- |
| `fatal: not a git repository` | 先 `git clone` bundle 或在仓库根执行 |
| 想看某个类“第一次出现” | `git log --oneline --follow -- <path>` |
| 想跳过中间提交直接看检查点 | `git checkout ba086b2`（C1）/ `ee173f6`（C2）/ `5a5c97b`（C3） |
| 自己敲的代码和教程不一致 | `git diff <教程sha> -- server` 只显示差异 |

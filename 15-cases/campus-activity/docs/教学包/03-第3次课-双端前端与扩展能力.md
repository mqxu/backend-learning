### 1.1 本课在课程中的位置

前两次课把「后端 + 数据库 + 安全缓存」跑通，学生看到的是 curl、Swagger 和测试脚本；这一次课让学生第一次**用浏览器看到自己的产品**。本课不是从零写前端，而是理解已有前端工程、接入四项扩展能力、完成跨端联调，并把联调过程沉淀成云效任务、缺陷单与测试用例。

> 第 2 次课后端跑通 → **本课双端联调并把过程变成质量资产** → 第 4 次课测试、部署与答辩。

> **「让学生能在浏览器里完成一次真实报名，让团委能看到封面与审核结果，让两组前端改动都从 `develop` 安全合入，并把发现的问题变成云效缺陷单与测试用例。」**

### 2.2 教学重点

1. **统一请求层**：`app/src/utils/request.ts` 的 `BASE_URL`、token 注入、401/403 处理、`uploadFile` 与 `resolveFileUrl` 是两端联调的地基。
2. **代理链路**：`app`、`admin` 两份 `vite.config.ts` 同时代理 `/api` 与 `/uploads` 到 `http://127.0.0.1:8016`。
3. **请求路径分工**：H5 走 `/api` 相对路径；小程序非 H5 走 `http://127.0.0.1:8016/api`；图片同理走相对地址或完整地址。
4. **三条新增链路**：封面上传（multipart）、短信登录（发码 + mockCode）、真实登出（jti 黑名单）。
5. **联调即质量**：每个问题都要落成云效缺陷单，每个修复都要有回归证据。

## 5 知识精讲

> 讲授总时长控制在 25 分钟以内，其余时间留给实操。

### 5.1 三端架构与一次请求的路径

```text
浏览器（Chrome）
├── 5174 H5（uni-app 编译产物 / Vite dev server）
│     └── fetch /api/**、<img src="/uploads/**">
│           └── Vite proxy ──► http://127.0.0.1:8016/api、/uploads
├── 5173 管理后台（Vue3 + Element Plus / Vite dev server）
│     └── axios /api/**、<img src="/uploads/**">
│           └── Vite proxy ──► http://127.0.0.1:8016/api、/uploads
└── （小程序真机/开发者工具）uni.request /api/** ──► http://127.0.0.1:8016/api
后端 8016（Spring Boot）
├── Spring Security + JWT
├── MySQL 3306（campus_activity，12 张表）
└── Redis 6379 database 11（缓存 / 验证码 / 黑名单 / 锁）
```

**要点 1：开发期不需要 CORS。** 页面与接口都通过同源 `/api` 发出，Vite 代理在开发服务器内部转发；生产期由 Nginx 同域反代 `/api`，同样不需要 CORS。
**要点 2：`/uploads` 必须与 `/api` 一起代理。** 后端上传返回相对地址 `/uploads/...`，只代理 `/api` 会让图片 404——这是本课最常见缺陷（DEF-2）。

### 5.7 短信验证码登录链路

```text
① POST /api/app/auth/sms/send-code  {"phone":"13800000003"}
      → SmsCodeService：手机号格式 ^1[3-9]\d{9}$ → 60 秒间隔 → 当日 ≤10 条
      → Redis Hash campus:sms:code:<phone>（300 秒）
      → Mock 通道 + expose-code=true 时响应带 data.mockCode
② POST /api/app/auth/sms/login  {"phone","code"}
      → verify：过期/已用/错误次数
      → 按手机号查 sys_user（没有则自动建号，role=STUDENT）
      → JwtUtil 签发 JWT（sub/role/orgId/昵称/jti/iat/exp，2 小时）
      → 返回 {token, needBind, user}
③ 前端：setToken + 存 user
      needBind=true → /pages/auth/bind；否则 switchTab 回首页
```

### 5.8 真实登出与 JWT 黑名单

```text
POST /api/app/auth/logout  （Authorization: Bearer <token>）
   → AuthService.logout：解析 jti 与 exp → 剩余有效期作为 TTL
   → Redis SET campus:auth:blacklist:<jti> = 1（TTL = 剩余有效期）
   → 之后同一 token 请求：JwtAuthenticationFilter 命中黑名单 → 按匿名处理 → 401 + 10001
```

小程序端 `app/src/utils/auth.ts`：

```ts
export async function logout(): Promise<void> {
  try {
    if (getToken()) await api.logout()   // best-effort：后端失败不阻断本地退出
  } catch (e) { /* 忽略 */ } finally {
    clearToken(); uni.reLaunch({ url: '/pages/index/index' })
  }
}
```

管理后台 `admin/src/layout/index.vue` 同理：确认弹窗 → `await logout()`（失败忽略）→ `clearAuth()` → 跳 `/login`。

**课堂提醒**：小程序 dev 模式首页会**自动 mock 登录**，退出后 `reLaunch` 首页又拿到新 token，看起来「没退出」。验证真实登出的正确方式是：在 Network 里确认 `POST /api/app/auth/logout` 返回 `code=0`，再用**旧 token** 调 `/api/app/user/profile` 观察 401。

### 5.9 前端错误处理与状态边界

表 3-15 前端三类错误的处理约定

| 类型 | HTTP | 前端动作 | 示例 |
| --- | --- | --- | --- |
| 认证失败 | 401 / 10001 | 清 token、提示「登录已过期」、跳登录（后台）或提示重新登录（小程序） | token 过期、登出后旧 token |
| 权限不足 | 403 / 10002 | 提示「没有操作权限」，不跳转 | 学生访问后台接口 |
| 业务失败 | 200 + 非 0 code | toast 后端 `message`，停留在当前页 | 60002、60005、70003、30001 |

**设计原则**：除网络异常外一律展示后端 `message`，前端不自己编错误文案。

### Step 10 两端真实登出与黑名单验证

**小程序端**：我的 → 退出登录。

```text
Network 预期：POST /api/app/auth/logout → {"code":0,"message":"ok"}
说明：退出后首页自动 mock 登录会生成新 token，这是 dev 模式特性，不代表登出失败。
```

**验证旧 token 失效（curl）**：

```bash
BASE=http://127.0.0.1:8016/api
# 1) 发码拿 mockCode（若提示 60002，先清限流 key 或等 60 秒）
CODE=$(curl -s -X POST "$BASE/app/auth/sms/send-code" \
  -H 'Content-Type: application/json' -d '{"phone":"13800000003"}' | jq -r '.data.mockCode')
# 2) 用验证码登录拿 token
T=$(curl -s -X POST "$BASE/app/auth/sms/login" \
  -H 'Content-Type: application/json' \
  -d "{\"phone\":\"13800000003\",\"code\":\"$CODE\"}" | jq -r '.data.token')
# 3) 登出后旧 token 立即失效
curl -s -X POST "$BASE/app/auth/logout" -H "Authorization: Bearer $T"   # 期望 code 0
curl -s "$BASE/app/user/profile" -H "Authorization: Bearer $T"          # 期望 401 + 10001
```

**Redis 黑名单检查**：

```bash
redis-cli -a abc123 --no-auth-warning -n 11 keys 'campus:auth:blacklist:*'
```

**管理后台端**：右上角用户 → 退出登录 → 确认。Network 应见 `POST /api/admin/auth/logout`，随后跳回登录页；用旧 token 调 `/api/admin/dashboard` 返回 401。

### Step 11 代理与 `/uploads` 验证（排障核心）

```bash
# 1) 直接访问后端静态资源（绕开前端代理）
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8016/uploads/<粘贴 objectKey>
# 期望 200；若 404，说明文件未落盘或 objectKey 抄错

# 2) 通过 H5 代理访问（等价于浏览器加载图片）
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5174/uploads/<objectKey>
# 期望 200；若 404，说明 vite.config.ts 缺少 /uploads 代理

# 3) 通过后台代理访问
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5173/uploads/<objectKey>
```

| 现象 | 结论 | 处理 |
| --- | --- | --- |
| 后端 200 / 前端 404 | 代理缺失 | 补 `/uploads` proxy，重启 dev server |
| 后端 404 / 前端 404 | 文件不存在 | 重新上传，核对 `storage-type=local` 与 `base-dir` |
| 后端 200 / 前端 200 | 正常 | 记录为检查点证据 |

**排错顺序（教给学生）**：

```text
① 服务在不在（ping/端口） → ② 请求发到哪（Network URL）

→ ⑤ 数据在哪（Redis key / MySQL / uploads 目录） → ⑥ 日志怎么说（后端 console）
```

**5 分钟原则**：同一问题超过 5 分钟，按上面六步把证据贴到小组群，由教师或相邻组集中解决。

| 某端启动失败（环境问题） | 用教师机器投屏演示，学生看第 7 章截图与代码 | 学生能讲清链路 |
| 网络/云效不可用 | 任务/缺陷/用例先用本地表格填写，课后补录云效 | 表格截图 |
| 上传始终失败 | 用已上传好的截图 + 说明链路，学生课后修复 | 缺陷单 + 修复计划 |
| 进度落后 20 分钟 | 砍掉 Step 8 四种 bizType，只演示 common 与 activity-cover | 检查点 1～5 仍可完成 |

**前后端任务拆开兜底**：若前端整体不可用，后端学生先用 curl 完成 Step 9/10（短信登录、登出黑名单），前端学生按代码走读完成「读代码 + 写缺陷单」；两组合并时再对接。

**演示账号兜底**：所有演示改用固定账号（`mock-organizer-1`、`admin/Admin@123`、13800000003），避免现场注册/换号浪费时间。

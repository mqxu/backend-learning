## 1 课程定位与对象

### 1.1 一句话定位

**用 16 学时，让 4–5 人小组在真实的云效协作平台上，把一个「学生报名、组织者发布、团委审核」的校园活动小程序从环境搭建一路做到 ECS 上线与答辩。**

课程选这个项目，是因为它在三个维度上都「真」：

| 维度 | 说明 | 学生能获得的可验证证据 |
| --- | --- | --- |
| 真项目 | 44 个 REST 接口、12 张表、三端（小程序 H5 / 管理后台 / Spring Boot）、短信验证码、文件上传、Redis、Spring Security，不是 DEMO 骨架 | 本地跑通 `mvn test` 20 个用例、`./scripts/smoke.sh` 33 项断言 |
| 真平台 | 需求、任务、缺陷、代码、MR、流水线、测试计划、部署全部在云效里留痕 | 云效项目看板、MR 评审记录、流水线运行记录、Testhub 测试计划 |
| 真交付 | 第 4 次课产出公网可访问的 URL 与 `v1.0.0` 发布记录，教师按量规打分，组间互评 | 线上 `http://<ECS-IP>/api/ping` 返回 `{"code":0,...}`、发布 tag、答辩 PPT |

本课程**不是** Java 语法课，也**不是**云效产品培训课。云效是学生完成工程的工具与考核证据来源；课堂重心在于「怎么拆任务、怎么写能通过评审的代码、怎么让流水线绿灯、怎么在 3 分钟内把成果讲清楚」。

### 1.2 适用对象与先修要求

| 类别 | 要求 | 不满足时的处理 |
| --- | --- | --- |
| 对象 | 计算机 / 软件工程 / 信息类本科大三、大四，或高职高年级；已完成至少 1 门后端开发课 + 1 门前端课 | 高职可裁掉 04 次课的 AppStack/效能洞察选讲内容，保留主链路 |
| 必备 1 | Java 基础（类、集合、异常、Maven 依赖管理） | 第 1 次课前发 2 小时预习材料（见 01 号文档附录） |
| 必备 2 | Spring Boot 做过一个 CRUD 项目（Controller/Service/Mapper 三层能看懂） | 允许对照 `server/` 目录结构讲解，但需在组内配 1 名后端强手 |
| 必备 3 | Vue3 基础（组件、props、`v-model`、axios/promise） | 第 3 次课前端任务按「模板改造」而不是「从零写页面」设计 |
| 必备 4 | 命令行与 Git 基本操作（clone / commit / push / branch） | 第 1 次课前布置 Git 热身任务，课内首次 MR 由教师陪跑一组 |
| 建议 | 了解 HTTP 状态码、JSON、数据库 SQL 基础、Linux 基础命令 | 第 1 次课知识精讲补 10 分钟 HTTP 与分层 |
| 加分 | 用过 Docker、Nginx、JWT、Redis | 作为小组 DevOps / 后端角色的优先人选 |

### 1.3 学时与工作量

| 项 | 数量 | 说明 |
| --- | --- | --- |
| 课堂学时 | 16 学时 = 4 次课 × 180 分钟 | 每次课 4 × 45 分钟，含 2 次 10 分钟课间 |
| 课后小组集中 | 每次课 2–3 小时，共 8–12 小时/组 | 建议固定为「课后第 2 天晚 2 小时线上会议 + 站会」 |
| 课后个人 | 每人每次课约 2 小时 | 环境补齐、代码、写文档、准备答辩 |
| 每人人时估算 | 约 30–35 人时 | 课堂 16 + 课后 14–19；4 人组合计约 130 人时 |
| 教师投入 | 首次开课约 12–16 小时（含 90 分钟备课 ×4）；复用开课约 4–6 小时 | 首次主要是云效组织初始化、环境验证、样例 ECS 准备 |

> 工作量口径用于向学生说明「这是一门课，不是一次作业」。若学校按 1 学分 = 16 学时折算，本课程可作为 1 学分实训或 2 学分课程中的项目模块，由任课教师按学校规定调整课后强度。

### 1.4 课程边界（明确不承诺的内容）

| 不承诺 | 原因 | 替代安排 |
| --- | --- | --- |
| 微信小程序真机发布与订阅消息 | 需要企业主体与模板 ID，教学环境不具备 | 第 3 次课用 H5 预览（5174）验收同一套页面；真机调试步骤参考 uni-app 官方文档（需自行配置 AppID 与合法域名） |
| 真实短信通道 | 容联云账号需实名与模板审核 | 默认 Mock 通道，验证码从响应 `mockCode` 或后端日志获取；真实通道配置见 12 号项目文档第 5.4 节 |
| 云效全部产品深度使用 | 16 学时不够 | 必做 Projex / Codeup / Flow / Testhub；Packages 与效能洞察为选讲 |
| 生产级高可用与安全加固 | 超出课程目标 | 06 号手册给单机部署 + 加固清单；安全加固作为扩展阅读 |
| 保证每组都有独立 ECS | 阿里云试用权益与学校预算不定 | 见 4.5 节三种主机方案；最低可用「教师 1 台演示机 + 组内本地验证」 |

### 2.3 项目式学习（PBL）设计理念

本课程采用「驱动问题 + 真实交付 + 迭代节奏 + 过程证据」的 PBL 结构，五条设计原则：

| 原则 | 具体做法 | 反例（本课程刻意避免） |
| --- | --- | --- |
| 真实驱动问题 | 开场给「校团委要在两周内上线活动报名平台，下周一验收」的情境，验收标准与量规当场公开 | 只讲技术点，学生不知道为什么做 |
| 完整交付物 | 每次课结束都有一个能演示的产物：环境报告 → 业务链路 → 双端可点 → 线上 URL | 每次课只交代码片段，最后拼不起来 |
| 迭代节奏 | Sprint 1（第 1–2 次课）跑通后端主链路；Sprint 2（第 3–4 次课）双端联调 + 上线 | 一次大作业拖到最后一周 |
| 过程可见 | 看板、MR、流水线、测试计划即评分证据，学生每天能看到自己的进度 | 只看最终代码，过程黑箱 |
| 角色与责任 | 4–5 人固定角色 + RACI + 互评系数，每人有明确交付 | 全组做同一件事，有人搭便车 |

**任务弧**（把 4 次课串成一条故事线）：

```
环境就绪 → 后端主链路（登录/活动/报名/签到）→ 双端可点（H5 + 后台 + 扩展能力）→ 测试与上线 → 答辩
   第1次课            第2次课                        第3次课                      第4次课
```

### 2.4 职业素养落点（可直接写进课程大纲）

| 素养 | 课堂动作 | 评价方式 |
| --- | --- | --- |
| 工程规范 | 第 1 次课讲提交规范与分支保护，第 2 次课起拒绝直接向 `main` push | 提交历史抽查 |

### 4.5 流水线、主机组与云资源方案

学生端操作见 05 号手册第 5 章，服务器侧操作见 [06-ECS部署与运维实操手册](06-ECS部署与运维实操手册.md)。教师只需选定一种方案并提前告知学生：

### 5.5 组内互评机制

| 项 | 规则 |
| --- | --- |
| 时点 | 每次课末 5 分钟 + 课程结束时 1 次总评 |
| 方式 | 匿名表（姓名/贡献分 1–5/一句话评价），教师汇总 |
| 维度 | 任务完成度、代码/文档质量、协作与响应、会议参与、诚信 |
| 系数 | 组员互评均分映射为 0.8–1.2：均分 ≥4.5→1.2，4.0–4.4→1.1，3.5–3.9→1.0，3.0–3.4→0.9，<3.0→0.8 |
| 异常 | 两人互评差距 >1.5 分或出现「全 5 分」，教师约谈并核对云效记录 |
| 用途 | 个人得分 = 小组得分 × 系数（见 6.6 节） |

> 互评只是系数，不是独立分数，避免「人缘分」直接影响总评；教师有最终核定权。

### 5.6 组间 PK 积分榜规则

积分榜公开在教室投影/班级群，每次课更新一次，**只作激励，不直接计入成绩**（成绩仍按 6 节量规）。

| 计分项 | 分值 | 判定 | 采集人 |
| --- | --- | --- | --- |
| 检查点全过 | 每课 +10 | 该课所有检查点按时通过 | 教师 |
| 首个跑通 `/api/ping` | +5（一次性） | 第 1 次课 | 教师 |
| 首个合并 MR | +5（一次性） | 第 1 次课内 | 教师 |
| 冒烟全绿 | +15（一次性） | `./scripts/smoke.sh` 输出「全部通过：33 项」 | 教师核验输出 |
| 测试用例数 | 每 5 条 +5，上限 +15 | Testhub 用例数（≥12 条为满） | 教师 |
| 缺陷闭环 | 每条 +3，上限 +15 | 缺陷单状态为已关闭 | 教师 |
| 流水线绿灯 | +10 | 首次成功运行 | 教师 |
| 上线成功 | +20 | 公网可访问 + 健康检查通过 | 教师 |
| 答辩投票 | 第 1 名 +10、第 2 名 +6、第 3 名 +3 | 组间互投（不得投自己） | 教师 |
| 扣分项 | 直接 push 保护分支 −10；看板 24 小时未更新 −5；提交信息不规范 −2/次 | 抽查 | 教师 |

示例：A 组第 1 次课拿到检查点 10 + 首个 ping 5 + 首个 MR 5 + 答辩未到 = 20 分；B 组第 4 次课累计 10+5+15+15+10+20+10=85 分。积分榜末尾两名可获得「补救任务清单」，优先获得教师答疑时段。

### 6.5 等级描述量规（统一四档）

用于需要给「等级」而非「分数」的场合（如课程大纲、五级制换算）。教师在每个维度按四档描述整体判断，再折算分数。

| 等级 | 分数区间 | 整体描述 | 典型表现 |
| --- | --- | --- | --- |
| A 优秀 | 90–100 | 全链路可用，过程证据完整，能解释设计取舍 | 冒烟 33/33、流水线绿灯、公网可用、问答能讲「为什么」、MR 有实质评审 |
| B 良好 | 80–89 | 主链路可用，个别环节需教师提示 | 测试通过但演示有卡顿、文档基本齐全、部署成功但回滚未演练 |
| C 及格 | 70–79 | 能演示部分链路，证据不全 | 只跑通后端或只跑通前端；看板滞后；评审仅形式；部署未完成 |
| D 不及格 | 60–69 | 交付物缺失较多 | 环境未通、无 MR、冒烟未跑、答辩讲不清分工 |
| F 不合格 | <60 | 基本未参与或无有效交付 | 组内任务零贡献（互评系数 0.8 且教师核实）、抄袭、伪造记录 |

> 等级区间为课程建议值，任课教师可按本校教务规定调整；调整后需在本文件版本记录中登记。

### 6.6 个人得分与系数计算

```
个人得分 = 小组得分 × 组内互评系数（0.8–1.2）
组内互评系数 = 映射(组员对该成员评分的平均值)   # 见 5.5 节
小组得分 = 过程 40 + 成果 40 + 答辩 20（按 6.1–6.4 逐项打分）
```

| 示例 | 小组得分 | 互评均分 | 系数 | 个人得分 |
| --- | --- | --- | --- | --- |
| 积极后端 | 86 | 4.6 | 1.2 | 103 → 按上限 100 计 |
| 正常参与 | 86 | 3.7 | 1.0 | 86 |
| 参与不足 | 86 | 3.2 | 0.9 | 77 |
| 长期缺席（教师核实） | 86 | 2.8 | 0.8 | 69，另按考勤处理 |

规则细节：
1. 系数上限 1.2、下限 0.8；个人得分超过 100 时按 100 计。
2. 组内互评系数由组员评分求均值后映射，教师可核减异常值（如恶意差评），核减需记录理由。
3. 个人零贡献（云效无任务、无提交、无会议记录且互评 <2.0）按不及格处理，由教师面谈确认。

```bash
redis-server --version # 期望 6.2+
redis-cli -a abc123 --no-auth-warning -n 11 ping   # PONG
curl -s http://127.0.0.1:8016/api/ping
# 期望 {"code":0,"message":"ok","data":{"service":"campus-activity","status":"up"}}
```

| 检查项 | 通过标准 | 常见失败 | 处理 |
| --- | --- | --- | --- |
| JDK | 21.x | 17 或 8 | 装 JDK21 并改 `JAVA_HOME` |
| Maven | 3.9.x | 未装/代理 | 用 U 盘安装包；配 `settings.xml` 镜像 |
| Node/pnpm | 18+/8+ | npm 代理超时 | 用 pnpm + 镜像；离线包兜底 |
| MySQL | 8.0+，库 `campus_activity` 12 张表 | 认证失败/未建库 | 按 01 号文档重导 `schema.sql`/`data.sql` |
| Redis | db 11 PONG | NOAUTH/连接拒绝 | 带密码 `-a abc123`、确认服务已起 |
| 后端 | `/api/ping` code=0 | 端口占用/JDK 版本 | 换端口需同步改前端代理，不推荐；优先杀占用进程 |

### 8.2 开场情境话术（第 1 次课，可直接念）

> 「校团委现在遇到一个问题：一场讲座 200 个名额，微信群里报名、人工统计、现场纸质签到，最后对不上账，还经常超员。下周一团委要验收一个能线上报名、扫码签到、后台审核的系统。
> 你们是承包这个项目的外包小组，我是团委负责人，也是你们的甲方。今天下课前，我要看到三样东西：每个人电脑上有一个能返回 `{"code":0}` 的后端；你们组有一个 24 条任务的可视化看板；至少一个已经合并的代码变更。
> 四次课后，这个系统要部署到真实服务器上，我会带人验收。做不到的部分现在说，我会记下来，但验收标准不会因此降低。」

后续课开场（30 秒）：
- 第 2 次：「甲方上周看到的是环境，今天要看业务流程能不能跑通一条。」
- 第 3 次：「今天开始这个系统要给真实学生用，界面能不能点、后台能不能审。」
- 第 4 次：「今天上线，公网可访问，然后你们要面对甲方的技术追问。」

### 8.7 常见卡点 5 分钟原则与卡点分流

| 卡点级别 | 判定 | 处理时限 | 处理方式 |
| --- | --- | --- | --- |
| L1 个人卡点 | 1 人卡住（装环境、命令报错） | 5 分钟 | 自己查 + 问组员；5 分钟未解举手 |
| L2 组内卡点 | 全组卡在同一问题（后端起不来、库连不上） | 10 分钟 | 组内换人复现；仍不行举手，教师优先处理 |
| L3 全班卡点 | ≥3 组同一问题（云效登录失败、网络代理） | 立即 | 停止实操，全班集中讲解 5–10 分钟；必要时切换降级方案 |

原则：**任何卡点 5 分钟未解必须升级，不允许一个学生沉默 20 分钟**。教师巡场时先问「卡了多久」，超过 5 分钟直接介入。

### 9.2 项目发布会（第 1 次课）

- **物料**：一页「团委需求清单」（5 条真实诉求）、验收标准表、倒计时 10 分钟。
- **流程**：教师以甲方身份念 5.2 节话术 → 展示 3 张目标页面截图（`app-home.png`、`admin-dashboard.png`、`app-org-checkin.png`）→ 公布 4 次课里程碑 → 学生组内 3 分钟讨论「我们组最大的风险是什么」并写在看板上。
- **评分**：每组把「最大风险」写进项目描述，教师点评 2 组；写得出具体风险（不是「怕来不及」）+2 积分。

### 9.3 缺陷狩猎赛（第 2/3 次课）

- **规则**：两组结对，A 组在 B 组环境上按「学生/组织者/管理员」身份乱操作 8 分钟，发现异常即在云效建缺陷单（标题 + 复现步骤 + 期望/实际）；B 组同样反击。
- **有效缺陷**：能复现、有步骤、非重复，教师判定后 +3 积分/条，上限 5 条。
- **预置弹药**：教师提供 8 条缺陷预案（如报名满员提示、签到码过期、上传非图片、越权访问、重复报名），防止低年级学生「找不到 bug」冷场。
- **收尾**：每组认领 2 条对方缺陷，第 3 次课前闭环。

### 9.4 代码评审马拉松（第 2 次课）

- **规则**：每组选 1 个 MR（关联任务号的 `feat/*`），由别组 1 人主评、本组 1 人记录；主评必须写 3 条：1 条肯定、1 条问题、1 条建议；10 分钟内完成。
- **评审清单**（发给学生）：接口路径是否与文档一致；是否新增未登记的错误码；有无调试代码/`System.out`；异常分支是否有提示；提交信息是否规范；是否关联任务号；前端是否有 `any` 泛滥；敏感信息是否入库。
- **评分**：被采纳的意见 +5 积分/组；只写「LGTM」不计分。

### 9.5 上线剪彩（第 4 次课）

- **规则**：各组在同一分钟打开自己的 `http://<ECS-IP>/`，教师投屏第一组成功页面，全班倒计时 3-2-1。
- **记录**：截图 + 记录访问时间，作为部署分证据。
- **兜底**：未上线组用本地 URL 参与「剪彩」，但部署分按 6.3.4 实评。

### 9.6 企业评审角色扮演（第 4 次课答辩）

| 角色 | 扮演者 | 提问方向 | 示例问题 |
| --- | --- | --- | --- |
| CTO | 教师 | 架构取舍与扩展性 | 「明年要接微信支付，你的表结构要改哪里？」 |

## 10 教学安全与学术诚信

| 风险 | 规则 | 教师动作 |
| --- | --- | --- |
| 学生共用云效账号 | 一人一号，禁止代登录、代提交 | 成员列表核对真实姓名 |
| 教师组织管理员账号泄露 | 教师账号不用于课堂演示登录；演示用学生账号 | 开启二次验证 |
| ECS SSH 私钥外泄 | 私钥只存云效主机组凭据，不发给学生 | 课后轮换密钥 |
| 演示密码被用于真实环境 | `admin/Admin@123` 等仅用于本地演示 | 课件与文档标注「仅演示」 |
| 机房机器残留数据 | 课后清理/关机 | 检查表 |

### 10.2 数据与隐私

| 项 | 要求 |
| --- | --- |
| 演示身份 | 只用项目内置演示数据（张小明/李小红/王大力等虚构身份），禁止录入真实身份证、真实手机号 |
| 学号 | 学号白名单为虚构编号（2023001 等），不与真实学籍关联 |
| 截图 | 上传到云效的截图不得包含真实个人信息 |
| 上传文件 | 只上传课程素材，禁止上传含敏感信息的文件；`/uploads` 仅本地/内网 |

### 10.3 云资源与成本

| 项 | 做法 |
| --- | --- |
| 免费额度 | 开课前确认组织权益（人数、流水线时长、主机部署）；超出后按云效计费规则处理 |
| ECS | 优先试用/包月；按量付费的机器课后立即关机或释放；教师统一建「课后释放」任务 |
| 存储 | 制品保留 30 天内即可；大文件不入库 |
| 预算告知 | 第 1 次课告知可能产生的费用与关闭方法 |
| 释放检查 | 第 4 次课后 1 周内核对：ECS、云效主机组、制品库、OSS（若用） |

### 10.4 学术诚信与 AI 使用边界

| 允许 | 禁止 | 核验方式 |
| --- | --- | --- |
| 用 AI 解释报错、生成测试数据、改写注释 | 用 AI 直接生成整份项目并当作自己完成 | 云效提交历史 + 现场问答（能讲清代码） |
| 参考网上教程与开源代码（注明来源） | 抄袭同班/往届代码（含变量名照抄） | 代码相似度抽查 + 口头答辩 |
| 组内共享环境配置与排错经验 | 组间直接复制代码与文档 | MR 记录、组间代码比对 |
| 使用 AI 辅助写文档，但需自己核对事实 | 伪造云效记录、截图、运行结果 | 现场重现 + 运行日志 |

处理：首次发现照抄 → 该项目维度记 0 并约谈；再次发现 → 按学校学术不端规定处理并记入课程记录。

### 10.5 设备与机房规范

上课前检查：电源、网络、投影、充电位；禁止在机房机器上装与课程无关的大型软件；下课前 5 分钟关机/注销；自带机注意电池与散热。

### 11.1 教学风险登记册

## 13 90 分钟备课路径

> 适用于已有一轮开课经验、只需准备某一次课；首次开课按 13.4 节扩展为 3–4 小时。

### 13.1 三遍法

| 遍 | 时间 | 目标 | 产出 |
| --- | --- | --- | --- |
| 第 1 遍 读 | 25 分钟 | 读课次文档（01/02/03/04）的「教学目标、时间表、复现步骤」三节 + 本文件第 3/8 节 | 在文档上标 3 个「今天必须讲清」和 2 个「可以不讲」 |
| 第 2 遍 做 | 35 分钟 | 在教师机上按课次文档 Step 走一遍关键路径（不追求全量），记录卡点 | 一份「教师演示脚本」（10 条命令/点击） |
| 第 3 遍 排 | 30 分钟 | 排 4 学时时间表：填检查点、分组演示顺序、降级预案、课后任务 | 一页纸课堂流程卡（附录 A） |

### 13.2 90 分钟分段时间表

| 时间 | 动作 | 检查点 |
| --- | --- | --- |
| 0–10 | 看课次文档封面信息表 + 事实清单相关章节（端口/账号/数量） | 能说出本课 3 个数字口径 |
| 10–25 | 读教学目标/重难点/时间表；标出讲授 ≤15 分钟的内容 | 讲授清单不超过 3 条 |
| 25–35 | 读复现步骤，标出教师机上必须提前跑通的 5 条命令 | 5 条命令写进流程卡 |
| 35–55 | 教师机实操：起环境 → 跑本课关键命令 → 截 2 张图备用 | 截图存 `教师备份/` |
| 55–65 | 读常见错误章节，圈出本班最可能出现的 3 条 | 3 条写进板书画重点 |
| 65–75 | 准备检查点表与积分项；确认分组与演示顺序 | 检查点表打印 |
| 75–85 | 准备课后任务（云效任务描述模板 + 截止时间） | 任务文案可直接粘贴 |
| 85–90 | 通读流程卡，模拟开场 3 分钟 | 能脱稿开场 |

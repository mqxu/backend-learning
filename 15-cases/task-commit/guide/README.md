# 结合 AI 实现 09-security

主文档是 [walkthrough.md](walkthrough.md)，一份文档自成一体。学生拿这一份和 AI，就能做出与本仓库 `09-security` 结构一致、行为一致的前后端。

不需要看别的文件，也不需要任何脚本。

## 文档里有什么

| 部分 | 内容 |
| --- | --- |
| 一、项目全貌 | 前后端目录树、每个后端与前端文件的职责和关键成员、前后端字段对应 |
| 二、规格 | 四张表的字段与约束、十一组接口、权限矩阵、错误码、三条不变式、前端路由 |
| 三、二十步 | 每步的提示词、产出文件、验收命令 |
| 四、验收 | 二十四条可直接执行的脚本、前端十项走查 |
| 五、常见错误 | 按认证、授权、归属、出参、前端分组，每条给自查方法 |

## 建议的顺序

1. 先读第一部分和第二部分，把结构和契约看一遍，别急着动手
2. 按第三部分逐步做，每步的验收过了再进下一步
3. 做完跑第四部分的脚本，二十四条全过，再按十项清单走查前端
4. 卡住时查第五部分

第三部分的提示词里写死了文件名、类名和方法签名，这些是给 AI 的边界，不要让它改名。实现的逻辑由 AI 写，跑不通自己改。

## teacher 目录

[teacher/](teacher/) 里是配套的教师材料，学生不用看：

| 文件 | 用途 |
| --- | --- |
| `README.md` | 分关卡发放节奏、每关给什么扣什么、怎么分辨作业是不是自己做的 |
| `contract.md` | 只给契约不给实现的分关卡版本，用于过程性教学 |
| `guide-01-auth.md` 到 `guide-04-frontend.md` | 四关任务卡，卡住时给三级提示 |
| `pitfalls.md` | 常见错误清单，与主文档第五部分同源 |
| `check.sh` | 二十四条验收脚本，与主文档第四部分同源，支持按关卡执行 |
| `ai-prompt.md` | 提问结构的展开讲解 |
| `spec-template.md` | 动手前填的规格说明表 |

主文档适合“做完这一章”的目标，teacher 目录适合“让学生自己想设计”的过程性教学。两者内容有重叠，选一种用。

# 关卡 4 · 前端

做完这一关，三个角色从浏览器登录进去，各自看到该看的页面，越权的操作被拦下来并给出合理提示。

后端已经能用了，这一关的重点是让前端的错误处理和后端的约定对上。

## 你手上有什么

- `contract.md` 里的响应格式、出参字段、401 与 403 的用法
- 前三关的后端接口
- 下面这张字段清单

## 字段清单

响应外壳：`code`、`message`、`data`。

登录返回：`token`、`tokenType`、`expiresAt`、`username`、`nickname`、`roles`。

账号：`username`、`nickname`、`roles`、`authorities`、`enabled`。任何接口都不带 `password`。

任务：

| 字段 | 类型 | 可空 |
| --- | --- | --- |
| `id` | number | 否 |
| `title` | string | 否 |
| `content` | string | 否 |
| `ownerId` | number | 否 |
| `owner` | string | 否 |
| `ownerNickname` | string | 否 |
| `status` | `'SUBMITTED'` 或 `'REVIEWED'` | 否 |
| `statusText` | string | 否 |
| `score` | number | 是 |
| `comment` | string | 是 |
| `submittedAt` | string | 否 |
| `reviewedAt` | string | 是 |

`status` 用来做逻辑判断，`statusText` 直接显示。后端已经把中文给出来了，前端不用再写一遍映射。

## 要做的东西

四块：工程配置、类型定义、请求层、页面。

**类型定义**先写，字段与后端出参一一对应。三个字段要允许为空：`score`、`comment`、`reviewedAt`。

**请求层**分两半：请求拦截器负责在每个请求上加令牌，响应拦截器负责拆外壳和分流错误。

**页面**四个：登录、学生任务列表、教师批改列表、管理账号。

**路由**要带守卫，未登录进不去业务页，角色不对进不去别人那页。

## 卡住了看这里

**第一个坎：页面显示“暂无数据”，控制台干净的**

打开网络面板，看请求打到哪个地址。如果返回的是一段 HTML，说明代理没配上，请求被开发服务器自己接了。

提示：后端有三组路径前缀，代理也要配三条，一一对上。`pitfalls.md` 最后一张表第一行。

**第二个坎：令牌过期后页面白屏**

未认证和越权在处理里用了同一个分支，页面不知道该干嘛。

提示：这两件事的处理完全不同。未认证要清登录态、跳登录页、记住来处；越权只弹提示，人还在原地。分开写。

**第三个坎：刷新就退出登录**

登录态只存在内存里，或者存了却没在应用启动时恢复。

提示：令牌存本地存储，应用启动时先读出来再决定渲染哪个页面，别一上来就按未登录渲染。

**第四个坎：类型检查报错一片**

后端的可空字段在前端写成了非空。

提示：只有 `id`、`title`、`content`、`owner`、`status`、`statusText`、`submittedAt` 这几个一定有值。分数、评语、批改时间在待批改时都是 null。

**第五个坎：用 127.0.0.1 打不开页面**

开发服务器只监听了 IPv6 回环。

提示：用 `localhost:5173`。

# 关卡 1 · 认证

做完这一关，系统能凭用户名密码换出一张令牌，用令牌能证明自己是谁，不用令牌进不来。

## 你手上有什么

- `contract.md` 里的登录接口、错误码、账号表结构
- 演示账号的密码（明文），库里存的是 BCrypt 密文
- `check.sh` 的第 1 到 10 条

## 要做到

| 编号 | 结果 |
| --- | --- |
| 1 | `/public/ping` 不登录也能访问 |
| 2-3 | 不登录访问任务接口返回 401，不是 500，不是 HTML |
| 4 | 登录返回令牌、类型、过期时间、角色 |
| 5-6 | 密码错和用户名不存在给同一个错误码 30001 |

| 8 | 参数缺失返回 400 和中文提示 |

## 建议的动作顺序

1. 先建表和种子数据，密码用 BCrypt 密文。可以写一段临时代码生成密文，也可以借助在线工具，但库里存的必须是 `$2a$` 开头的字符串。
2. 从库里把“账号 + 角色”读出来，拼成安全框架认识的用户对象。这里会遇到一个设计问题：实体是一张表的映射，而认证需要账号和角色两个信息，怎么合。
3. 配密码编码器，验证一次“同一个密码加密两次结果不同，但都能校验通过”。
4. 把登录接口写出来，先只返回一个写死的字符串，确认路由和放行规则通了。
5. 再接令牌签发。签名密钥放配置文件，不要写在代码里。
6. 最后写过滤器：从请求头取令牌、验签、查账号、放进上下文。顺序错了或者异常没兜住，就会出现 401 返回 HTML 的情况。

第 2 步和第 6 步是这一关的两个坎。

## 卡住了看这里

**第一个坎：用户对象怎么组装**

认证框架要的是 `UserDetails`，它有 `getUsername`、`getPassword`、`getAuthorities`、`isEnabled` 几个方法。你的实体里有账号信息，角色在另一张表。

问题是：让实体去实现 `UserDetails`，还是另起一个类？

提示：让实体实现接口，等于把“表结构”和“安全框架的约定”绑在一起。将来表加一个字段，或者换个认证方式，两边都得改。

**第二个坎：授权字符串长什么样**

`getAuthorities()` 要返回字符串集合。你手上有两类东西：角色（STUDENT、TEACHER、ADMIN）和权限点（task:submit 这类）。

提示：两类都要放进去，但角色的字符串要带 `ROLE_` 前缀。想清楚为什么，再看 `pitfalls.md` 里 `hasRole` 那一条。

**第三个坎：401 变成了 HTML**

请求没带令牌，浏览器却收到一坨 HTML。

提示：安全框架的默认行为是跳到登录页，前后端分离时这个跳转没意义。要去配置里指定“未认证时返回什么”，自己写一个返回 JSON 的处理器。
